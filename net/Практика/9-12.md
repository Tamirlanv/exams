# Сетевое администрирование · практика 9–12

## Задание 9

Настройте DHCP-сервис для локальной сети: задайте пул адресов, шлюз и DNS, затем получите параметры на клиенте.

### Решение

**Среда:** Cisco Packet Tracer, маршрутизаторы 2911, коммутаторы 2960, PC-PT. Имена портов относятся к этим моделям. Для PC–SW и SW–R используйте Copper Straight-Through, для R–R/SW–SW — Copper Cross-Over или автоматический выбор. Дождитесь зелёных индикаторов. Команды show выполняются из привилегированного режима `#`; на запрос имени при сохранении нажмите Enter.

**Схема:** R1 Gi0/0 — SW1 Gi0/1; PC Fa0 — SW1 Fa0/1; Server-PT Fa0 — SW1 Fa0/2. Серверу задайте 192.168.10.53/24, шлюз .1; Services → DNS → On и запись A `server.lab.test` → 192.168.10.53.

**R1 — CLI:**

```cisco
enable
configure terminal
interface g0/0
 ip address 192.168.10.1 255.255.255.0
 no shutdown
 exit
ip dhcp excluded-address 192.168.10.1 192.168.10.99
ip dhcp pool LAN10
 network 192.168.10.0 255.255.255.0
 default-router 192.168.10.1
 dns-server 192.168.10.53
 exit
end
copy running-config startup-config
```
На PC выберите Desktop → IP Configuration → DHCP, затем выполните `ipconfig /all`, `ping 192.168.10.1`, `nslookup server.lab.test`. Если модель PC не поддерживает /all, посмотрите поля в IP Configuration.

**Проверка:** на R1 `show ip dhcp binding`, `show ip dhcp pool`. Адрес клиента из .100–.254, маска /24, шлюз .1, DNS .53. DNS-сервер находится вне выдаваемого диапазона. Если аренда отсутствует, проверьте порт, VLAN, интерфейс R1 и свободные адреса пула.

## Задание 10

Настройте DNS-службу в локальной сети: создайте запись имени для сервера и проверьте разрешение имени с клиента.

### Решение

**Среда:** Cisco Packet Tracer, маршрутизаторы 2911, коммутаторы 2960, PC-PT. Имена портов относятся к этим моделям. Для PC–SW и SW–R используйте Copper Straight-Through, для R–R/SW–SW — Copper Cross-Over или автоматический выбор. Дождитесь зелёных индикаторов. Команды show выполняются из привилегированного режима `#`; на запрос имени при сохранении нажмите Enter.

**Схема:** PC, DNS Server-PT и Web Server-PT подключены к SW1 Fa0/1, Fa0/2, Fa0/3 соответственно; маршрутизатор для одной подсети не нужен.

На PC откройте **Desktop → IP Configuration → Static**, введите:

| Узел | IPv4 | Маска | Шлюз |
|---|---|---|---|
| PC | 192.168.10.10 | 255.255.255.0 | не нужен |
| DNS | 192.168.10.53 | 255.255.255.0 | не нужен |
| WEB | 192.168.10.80 | 255.255.255.0 | не нужен |
На DNS в Services → DNS включите службу, создайте A-запись `www.lab.test` со значением 192.168.10.80 и нажмите Add. На WEB включите Services → HTTP. Клиенту в IP Configuration укажите DNS 192.168.10.53.

**Проверка:** `ping 192.168.10.53`, `nslookup www.lab.test`, `ping www.lab.test`; в браузере PC откройте `http://www.lab.test`. Ожидается ответ A=192.168.10.80 и страница сервера. Суффикс .test выбран для учебной зоны; внешний DNS такую частную запись не обслуживает.

## Задание 11

Настройте NAT для доступа узлов внутренней сети к внешней сети и проверьте преобразование адресов.

### Решение

**Среда:** Cisco Packet Tracer, маршрутизаторы 2911, коммутаторы 2960, PC-PT. Имена портов относятся к этим моделям. Для PC–SW и SW–R используйте Copper Straight-Through, для R–R/SW–SW — Copper Cross-Over или автоматический выбор. Дождитесь зелёных индикаторов. Команды show выполняются из привилегированного режима `#`; на запрос имени при сохранении нажмите Enter.

**Оборудование:** R1 (граница), ISP (2911), SW1, PC1, PC2, внешний Server-PT. **Схема:**

```text
PC1/PC2 — SW1 Fa0/1–2; SW1 Gi0/1 — R1 Gi0/0
R1 Gi0/1: 203.0.113.2/29 — ISP Gi0/0: 203.0.113.1/29
ISP Gi0/1: 198.51.100.1/24 — Server: 198.51.100.10/24
```

На PC откройте **Desktop → IP Configuration → Static**, введите:

| Узел | IPv4 | Маска | Шлюз |
|---|---|---|---|
| PC1 | 192.168.10.10 | 255.255.255.0 | 192.168.10.1 |
| PC2 | 192.168.10.11 | 255.255.255.0 | 192.168.10.1 |
| Server | 198.51.100.10 | 255.255.255.0 | 198.51.100.1 |
На Server включите HTTP. Внешние адреса являются документальными диапазонами для изолированного стенда, не реальным подключением к Интернету.

**ISP — CLI:**

```cisco
enable
configure terminal
interface g0/0
 ip address 203.0.113.1 255.255.255.248
 no shutdown
 exit
interface g0/1
 ip address 198.51.100.1 255.255.255.0
 no shutdown
 exit
end
copy running-config startup-config
```

**R1 — CLI:**

```cisco
enable
configure terminal
interface g0/0
 ip address 192.168.10.1 255.255.255.0
 no shutdown
 exit
interface g0/0
 ip nat inside
 exit
interface g0/1
 ip address 203.0.113.2 255.255.255.248
 no shutdown
 exit
interface g0/1
 ip nat outside
 exit
ip route 0.0.0.0 0.0.0.0 203.0.113.1
ip nat inside source static 192.168.10.10 203.0.113.3
end
copy running-config startup-config
```
**Проверка:** с PC1 `ping 198.51.100.10` и откройте `http://198.51.100.10`. На R1 выполните `show ip nat translations` и `show ip nat statistics`: соответствие inside local 192.168.10.10 ↔ inside global 203.0.113.3. Внешний адрес .3 входит в подключённую к ISP /29; IOS NAT отвечает за него proxy ARP. PC2 не имеет правила NAT и в этой работе не получает внешний доступ. Это статический NAT 1:1, без overload.

Справка: [Cisco — настройка NAT/PAT](https://www.cisco.com/c/en/us/support/docs/ip/network-address-translation-nat/13772-12.html).

## Задание 12

Настройте PAT для нескольких внутренних узлов, использующих один внешний адрес, и проверьте доступ к внешнему ресурсу.

### Решение

**Среда:** Cisco Packet Tracer, маршрутизаторы 2911, коммутаторы 2960, PC-PT. Имена портов относятся к этим моделям. Для PC–SW и SW–R используйте Copper Straight-Through, для R–R/SW–SW — Copper Cross-Over или автоматический выбор. Дождитесь зелёных индикаторов. Команды show выполняются из привилегированного режима `#`; на запрос имени при сохранении нажмите Enter.

**Оборудование:** R1 (граница), ISP (2911), SW1, PC1, PC2, внешний Server-PT. **Схема:**

```text
PC1/PC2 — SW1 Fa0/1–2; SW1 Gi0/1 — R1 Gi0/0
R1 Gi0/1: 203.0.113.2/29 — ISP Gi0/0: 203.0.113.1/29
ISP Gi0/1: 198.51.100.1/24 — Server: 198.51.100.10/24
```

На PC откройте **Desktop → IP Configuration → Static**, введите:

| Узел | IPv4 | Маска | Шлюз |
|---|---|---|---|
| PC1 | 192.168.10.10 | 255.255.255.0 | 192.168.10.1 |
| PC2 | 192.168.10.11 | 255.255.255.0 | 192.168.10.1 |
| Server | 198.51.100.10 | 255.255.255.0 | 198.51.100.1 |
На Server включите HTTP. Внешние адреса являются документальными диапазонами для изолированного стенда, не реальным подключением к Интернету.

**ISP — CLI:**

```cisco
enable
configure terminal
interface g0/0
 ip address 203.0.113.1 255.255.255.248
 no shutdown
 exit
interface g0/1
 ip address 198.51.100.1 255.255.255.0
 no shutdown
 exit
end
copy running-config startup-config
```

**R1 — CLI:**

```cisco
enable
configure terminal
interface g0/0
 ip address 192.168.10.1 255.255.255.0
 no shutdown
 exit
interface g0/0
 ip nat inside
 exit
interface g0/1
 ip address 203.0.113.2 255.255.255.248
 no shutdown
 exit
interface g0/1
 ip nat outside
 exit
ip route 0.0.0.0 0.0.0.0 203.0.113.1
access-list 1 permit 192.168.10.0 0.0.0.255
ip nat inside source list 1 interface g0/1 overload
end
copy running-config startup-config
```
**Проверка:** одновременно откройте HTTP-сервер с PC1 и PC2, выполните ping. На R1: `show ip nat translations`, `show ip nat statistics`. У обоих клиентов inside global будет 203.0.113.2, а порты/идентификаторы сеансов различаются. ACL 1 здесь выбирает адреса для NAT и сама не прикрепляется к интерфейсу как фильтр. При отсутствии записей проверьте inside/outside и маршрут по умолчанию.

Справка: [Cisco — настройка NAT/PAT](https://www.cisco.com/c/en/us/support/docs/ip/network-address-translation-nat/13772-12.html).
