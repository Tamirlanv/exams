# Сетевое администрирование · практика 9–12

## Задание 9

Настройте DHCP-сервис для локальной сети: задайте пул адресов, шлюз и DNS, затем получите параметры на клиенте.

### Решение

#### Шаг 1. Добавьте оборудование

Откройте Cisco Packet Tracer → **File → New** (Файл → Новый). Внизу слева выбирайте категорию, затем модель и щёлкайте по свободному месту рабочего поля.

- **Компьютеры: 1 шт.** Нажмите **End Devices (Конечные устройства)**, выберите **PC-PT**. Имена в инструкции: **PC**.
- **Свитчи: 1 шт.** Нажмите **Network Devices → Switches (Сетевые устройства → Коммутаторы)**, выберите **2960**. Имена в инструкции: **SW1**.
- **Маршрутизаторы: 1 шт.** Нажмите **Network Devices → Routers (Маршрутизаторы)**, выберите **2911**. Имена в инструкции: **R1**.
- **Серверы: 1 шт.** Нажмите **End Devices (Конечные устройства)**, выберите **Server-PT**. Имена в инструкции: **Server**.

Чтобы задать имя, щёлкните по устройству → **Config → Display Name**, введите нужное имя и закройте окно. Название **свитч** и **коммутатор** означает одно и то же устройство: оно соединяет компьютеры. Маршрутизатор соединяет разные сети.

#### Шаг 2. Соедините устройства кабелями

Внизу слева нажмите **Connections** (значок молнии). Для каждой строки ниже заново выберите указанный кабель, затем щёлкните первое устройство и его разъём, после этого — второе устройство и его разъём.

1. Выберите **Copper Straight-Through (прямой медный кабель)**. Нажмите **PC → FastEthernet0**, затем **SW1 → FastEthernet0/1**.
2. Выберите **Copper Straight-Through (прямой медный кабель)**. Нажмите **Server → FastEthernet0**, затем **SW1 → FastEthernet0/2**.
3. Выберите **Copper Straight-Through (прямой медный кабель)**. Нажмите **SW1 → GigabitEthernet0/1**, затем **R1 → GigabitEthernet0/0**.

Разъём также называется **портом**. В командах `g0/0` — короткая запись GigabitEthernet0/0, `fa0/1` — FastEthernet0/1. У свитча индикатор может сначала быть оранжевым. Разъёмы маршрутизатора станут зелёными после команды `no shutdown` ниже — до настройки красный индикатор здесь допустим.

#### Что означают слова в этом задании

DHCP автоматически выдаёт компьютеру IP-адрес и другие настройки. «Пул» — набор адресов, которые разрешено выдавать. «Аренда» — выданный конкретному компьютеру адрес на определённое время.

#### Шаг 3. Настройте сервер

Нажмите сервер **Server → Desktop → IP Configuration → Static**. Введите **IP Address: 192.168.10.53**, **Subnet Mask: 255.255.255.0**, **Default Gateway: 192.168.10.1**.

Откройте **Services → DNS**, выберите **On**. В поле **Name** введите `server.lab.test`, в **Type** оставьте `A Record`, в **Address** введите адрес этого сервера. Нажмите **Add**. DNS — служба, которая переводит имя сайта в IP-адрес.

#### Что делают основные команды

`ip dhcp pool` создаёт набор выдаваемых адресов. `default-router` сообщает компьютерам адрес шлюза, `dns-server` — адрес службы имён. `excluded-address` исключает адреса, которые нельзя выдавать автоматически.

#### Как вводить команды на свитче или маршрутизаторе

1. Нажмите **устройство, названное перед блоком команд**.
2. Откройте вкладку **CLI** — это окно для ввода команд.
3. Нажмите Enter. Если появится `Would you like to enter the initial configuration dialog? [yes/no]:`, напишите `no` и нажмите Enter. При сообщении `Press RETURN to get started` ещё раз нажмите Enter. Если ещё идёт загрузка, дождитесь приглашения ввода.
4. Вводите строки блока сверху вниз, нажимая **Enter после каждой**. Копируйте только команды внутри блока. Надписи вида `Router>` или `Router#` устройство выводит само.
5. Команда `enable` открывает расширенный режим, `configure terminal` — настройку, `interface` выбирает разъём, `ip address` задаёт ему адрес, `no shutdown` включает разъём, `exit` возвращает на уровень выше, `end` завершает настройку.
6. Последняя команда `copy running-config startup-config` сохраняет настройки. На вопрос `Destination filename [startup-config]?` нажмите **Enter**, дождитесь `[OK]`.

Если ниже снова открываете то же устройство для исправления, начните с указанного блока. Команды проверки `show ...` вводятся после выхода из настройки командой `end`, когда строка заканчивается `#`; если видите `>`, сначала введите `enable`.

#### Настройте маршрутизатор R1

Нажмите **R1 → CLI**. Выполните следующие команды **на этом устройстве**, по одной строке:


```cisco
enable
configure terminal
interface g0/0
 ip address 192.168.10.1 255.255.255.0
 no shutdown
 exit
ip dhcp excluded-address 192.168.10.1 192.168.10.99
ip dhcp pool LAN10
 network 192.168.10.0 255.255.255.0
 default-router 192.168.10.1
 dns-server 192.168.10.53
 exit
end
copy running-config startup-config
```
Нажмите **PC → Desktop → IP Configuration → DHCP** и дождитесь появления адреса. Закройте это окно, откройте **Desktop → Command Prompt** и по очереди выполните `ipconfig /all`, `ping 192.168.10.1`, `nslookup server.lab.test`. Если модель PC не поддерживает /all, посмотрите поля в IP Configuration.

#### Где выполнять проверку

- **На компьютере:** нажмите его значок → **Desktop → Command Prompt** (Командная строка). Введите приведённую ниже команду `ping ...` и нажмите Enter. `Reply from ...` означает, что ответ получен; `Request timed out` — ответа нет. Первый запрос иногда не успевает пройти, поэтому повторите проверку.
- **На маршрутизаторе или свитче:** нажмите устройство → **CLI**. Для команд `show ...` используйте режим `#`, как объяснено выше.
- **Для страницы сайта:** нажмите компьютер → **Desktop → Web Browser**, введите адрес из задания и нажмите **Go**. Адрес сайта не вводят в CLI маршрутизатора.

**Проверка:** на R1 `show ip dhcp binding`, `show ip dhcp pool`. Адрес клиента из .100–.254, маска /24, шлюз .1, DNS .53. DNS-сервер находится вне выдаваемого диапазона. Если аренда отсутствует, проверьте порт, VLAN, интерфейс R1 и свободные адреса пула.

**Сохраните работу:** Packet Tracer → **File → Save As**, выберите папку и имя `Задание-9.pkt`. Это сохраняет всю схему; команды `copy ...` выше сохраняют настройки внутри отдельных устройств.

## Задание 10

Настройте DNS-службу в локальной сети: создайте запись имени для сервера и проверьте разрешение имени с клиента.

1. Выберите **Copper Straight-Through (прямой медный кабель)**. Нажмите **PC → FastEthernet0**, затем **SW1 → FastEthernet0/1**.
2. Выберите **Copper Straight-Through (прямой медный кабель)**. Нажмите **DNS → FastEthernet0**, затем **SW1 → FastEthernet0/2**.
3. Выберите **Copper Straight-Through (прямой медный кабель)**. Нажмите **WEB → FastEthernet0**, затем **SW1 → FastEthernet0/3**.

#### Шаг 3. Укажите адреса устройств

Для **каждого** компьютера или сервера из таблицы:

1. Щёлкните по его значку на схеме.
2. Откройте вкладку **Desktop** (Рабочий стол).
3. Нажмите **IP Configuration** (Настройка IP) и выберите **Static** (Вручную).
4. Перепишите значения **из строки именно этого устройства**: «IPv4» → **IPv4 Address / IP Address**, «Маска» → **Subnet Mask**, «Шлюз» → **Default Gateway**.
5. Если у шлюза написано «не нужен», оставьте поле пустым или 0.0.0.0. Остальные поля без указания не меняйте. Закройте окно — значения сохраняются автоматически.

IP-адрес — номер устройства в сети. Маска показывает границы его сети. Шлюз — адрес маршрутизатора, через который компьютер обращается в другие сети. Запись `/24` в пояснениях означает маску 255.255.255.0, `/30` — 255.255.255.252, `/29` — 255.255.255.248. В поля таблицы вводите обычные адреса и маски, без `/24`.


| Узел | IPv4 | Маска | Шлюз |
|---|---|---|---|
| PC | 192.168.10.10 | 255.255.255.0 | не нужен |
| DNS | 192.168.10.53 | 255.255.255.0 | не нужен |
| WEB | 192.168.10.80 | 255.255.255.0 | не нужен |
#### Настройте имена сайтов и веб-сервер

1. Нажмите **DNS → Services → DNS → On**.
2. В поле **Name** напишите `www.lab.test`, **Type** — `A Record`, **Address** — `192.168.10.80`. Нажмите **Add**. Это связь имени сайта с адресом сервера.
3. Нажмите **WEB → Services → HTTP**, выберите **On**.
4. Нажмите **PC → Desktop → IP Configuration**, в поле **DNS Server** введите `192.168.10.53`.

#### Где выполнять проверку

- **На компьютере:** нажмите его значок → **Desktop → Command Prompt** (Командная строка). **Проверка:** `ping 192.168.10.53`, `nslookup www.lab.test`, `ping www.lab.test`; в браузере PC откройте `http://www.lab.test`. Ожидается ответ A=192.168.10.80 и страница сервера. Суффикс .test выбран для учебной зоны; внешний DNS такую частную запись не обслуживает.

## Задание 11

Настройте NAT для доступа узлов внутренней сети к внешней сети и проверьте преобразование адресов.

### Решение

#### Шаг 1. Добавьте оборудование

Откройте Cisco Packet Tracer → **File → New** (Файл → Новый). Внизу слева выбирайте категорию, затем модель и щёлкайте по свободному месту рабочего поля.

- **Свитчи: 1 шт.** Нажмите **Network Devices → Switches (Сетевые устройства → Коммутаторы)**, выберите **2960**. Имена в инструкции: **SW1**.
- **Маршрутизаторы: 2 шт.** Нажмите **Network Devices → Routers (Маршрутизаторы)**, выберите **2911**. Имена в инструкции: **R1, ISP**.
- **Серверы: 1 шт.** Нажмите **End Devices (Конечные устройства)**, выберите **Server-PT**. Имена в инструкции: **Server**.

Чтобы задать имя, щёлкните по устройству → **Config → Display Name**, введите нужное имя и закройте окно. Название **свитч** и **коммутатор** означает одно и то же устройство: оно соединяет компьютеры. Маршрутизатор соединяет разные сети.

#### Шаг 2. Соедините устройства кабелями

1. Выберите **Copper Straight-Through (прямой медный кабель)**. Нажмите **PC1 → FastEthernet0**, затем **SW1 → FastEthernet0/1**.

3. Выберите **Copper Straight-Through (прямой медный кабель)**. Нажмите **SW1 → GigabitEthernet0/1**, затем **R1 → GigabitEthernet0/0**.

#### Что означают слова в этом задании

NAT заменяет внутренний адрес компьютера внешним. PAT позволяет нескольким компьютерам пользоваться одним внешним адресом. Устройство ISP в примере играет роль маршрутизатора провайдера; реальный Интернет не требуется.

- **Для страницы сайта:** нажмите компьютер → **Desktop → Web Browser**, введите адрес из задания и нажмите **Go**. Адрес сайта не вводят в CLI маршрутизатора.

**Проверка:** с PC1 `ping 198.51.100.10` и откройте `http://198.51.100.10`. На R1 выполните `show ip nat translations` и `show ip nat statistics`: соответствие inside local 192.168.10.10 ↔ inside global 203.0.113.3. Внешний адрес .3 входит в подключённую к ISP /29; IOS NAT отвечает за него proxy ARP. PC2 не имеет правила NAT и в этой работе не получает внешний доступ. Это статический NAT 1:1, без overload.

Справка: [Cisco — настройка NAT/PAT](https://www.cisco.com/c/en/us/support/docs/ip/network-address-translation-nat/13772-12.html).

**Сохраните работу:** Packet Tracer → **File → Save As**, выберите папку и имя `Задание-11.pkt`. Это сохраняет всю схему; команды `copy ...` выше сохраняют настройки внутри отдельных устройств.

## Задание 12

Настройте PAT для нескольких внутренних узлов, использующих один внешний адрес, и проверьте доступ к внешнему ресурсу.

### Решение

#### Шаг 1. Добавьте оборудование

Откройте Cisco Packet Tracer → **File → New** (Файл → Новый). Внизу слева выбирайте категорию, затем модель и щёлкайте по свободному месту рабочего поля.

- **Компьютеры: 2 шт.** Нажмите **End Devices (Конечные устройства)**, выберите **PC-PT**. Имена в инструкции: **PC1, PC2**.
- **Свитчи: 1 шт.** Нажмите **Network Devices → Switches (Сетевые устройства → Коммутаторы)**, выберите **2960**. Имена в инструкции: **SW1**.
- **Маршрутизаторы: 2 шт.** Нажмите **Network Devices → Routers (Маршрутизаторы)**, выберите **2911**. Имена в инструкции: **R1, ISP**.
- **Серверы: 1 шт.** Нажмите **End Devices (Конечные устройства)**, выберите **Server-PT**. Имена в инструкции: **Server**.

Чтобы задать имя, щёлкните по устройству → **Config → Display Name**, введите нужное имя и закройте окно. Название **свитч** и **коммутатор** означает одно и то же устройство: оно соединяет компьютеры. Маршрутизатор соединяет разные сети.

#### Шаг 2. Соедините устройства кабелями

Внизу слева нажмите **Connections** (значок молнии). Для каждой строки ниже заново выберите указанный кабель, затем щёлкните первое устройство и его разъём, после этого — второе устройство и его разъём.

1. Выберите **Copper Straight-Through (прямой медный кабель)**. Нажмите **PC1 → FastEthernet0**, затем **SW1 → FastEthernet0/1**.
2. Выберите **Copper Straight-Through (прямой медный кабель)**. Нажмите **PC2 → FastEthernet0**, затем **SW1 → FastEthernet0/2**.
3. Выберите **Copper Straight-Through (прямой медный кабель)**. Нажмите **SW1 → GigabitEthernet0/1**, затем **R1 → GigabitEthernet0/0**.
4. Выберите **Copper Cross-Over (перекрёстный медный кабель)**. Нажмите **R1 → GigabitEthernet0/1**, затем **ISP → GigabitEthernet0/0**.
5. Выберите **Copper Cross-Over (перекрёстный медный кабель)**. Нажмите **ISP → GigabitEthernet0/1**, затем **Server → FastEthernet0**.

Разъём также называется **портом**. В командах `g0/0` — короткая запись GigabitEthernet0/0, `fa0/1` — FastEthernet0/1. У свитча индикатор может сначала быть оранжевым. Разъёмы маршрутизатора станут зелёными после команды `no shutdown` ниже — до настройки красный индикатор здесь допустим.

#### Что означают слова в этом задании

NAT заменяет внутренний адрес компьютера внешним. PAT позволяет нескольким компьютерам пользоваться одним внешним адресом. Устройство ISP в примере играет роль маршрутизатора провайдера; реальный Интернет не требуется.

#### Шаг 3. Укажите адреса устройств

Для **каждого** компьютера или сервера из таблицы:

1. Щёлкните по его значку на схеме.
2. Откройте вкладку **Desktop** (Рабочий стол).
3. Нажмите **IP Configuration** (Настройка IP) и выберите **Static** (Вручную).
4. Перепишите значения **из строки именно этого устройства**: «IPv4» → **IPv4 Address / IP Address**, «Маска» → **Subnet Mask**, «Шлюз» → **Default Gateway**.
5. Если у шлюза написано «не нужен», оставьте поле пустым или 0.0.0.0. Остальные поля без указания не меняйте. Закройте окно — значения сохраняются автоматически.

IP-адрес — номер устройства в сети. Маска показывает границы его сети. Шлюз — адрес маршрутизатора, через который компьютер обращается в другие сети. Запись `/24` в пояснениях означает маску 255.255.255.0, `/30` — 255.255.255.252, `/29` — 255.255.255.248. В поля таблицы вводите обычные адреса и маски, без `/24`.


| Узел | IPv4 | Маска | Шлюз |
|---|---|---|---|
| PC1 | 192.168.10.10 | 255.255.255.0 | 192.168.10.1 |
| PC2 | 192.168.10.11 | 255.255.255.0 | 192.168.10.1 |
| Server | 198.51.100.10 | 255.255.255.0 | 198.51.100.1 |
Нажмите **Server → Services → HTTP → On** — так включается сайт для проверки. Внешние адреса являются документальными диапазонами для изолированного стенда, не реальным подключением к Интернету.

#### Что делают основные команды

`ip route` задаёт путь к другой сети: после команды идут адрес этой сети, её маска и адрес соседнего маршрутизатора, которому передать данные.

#### Как вводить команды на свитче или маршрутизаторе

1. Нажмите **устройство, названное перед блоком команд**.
2. Откройте вкладку **CLI** — это окно для ввода команд.
3. Нажмите Enter. Если появится `Would you like to enter the initial configuration dialog? [yes/no]:`, напишите `no` и нажмите Enter. При сообщении `Press RETURN to get started` ещё раз нажмите Enter. Если ещё идёт загрузка, дождитесь приглашения ввода.
4. Вводите строки блока сверху вниз, нажимая **Enter после каждой**. Копируйте только команды внутри блока. Надписи вида `Router>` или `Router#` устройство выводит само.
5. Команда `enable` открывает расширенный режим, `configure terminal` — настройку, `interface` выбирает разъём, `ip address` задаёт ему адрес, `no shutdown` включает разъём, `exit` возвращает на уровень выше, `end` завершает настройку.
6. Последняя команда `copy running-config startup-config` сохраняет настройки. На вопрос `Destination filename [startup-config]?` нажмите **Enter**, дождитесь `[OK]`.

Если ниже снова открываете то же устройство для исправления, начните с указанного блока. Команды проверки `show ...` вводятся после выхода из настройки командой `end`, когда строка заканчивается `#`; если видите `>`, сначала введите `enable`.

#### Настройте маршрутизатор ISP

Нажмите **ISP → CLI**. Выполните следующие команды **на этом устройстве**, по одной строке:


```cisco
enable
configure terminal
interface g0/0
 ip address 203.0.113.1 255.255.255.248
 no shutdown
 exit
interface g0/1
 ip address 198.51.100.1 255.255.255.0
 no shutdown
 exit
end
copy running-config startup-config
```

#### Настройте маршрутизатор R1

Нажмите **R1 → CLI**. Выполните следующие команды **на этом устройстве**, по одной строке:


```cisco
enable
configure terminal
interface g0/0
 ip address 192.168.10.1 255.255.255.0
 no shutdown
 exit
interface g0/0
 ip nat inside
 exit
interface g0/1
 ip address 203.0.113.2 255.255.255.248
 no shutdown
 exit
interface g0/1
 ip nat outside
 exit
ip route 0.0.0.0 0.0.0.0 203.0.113.1
access-list 1 permit 192.168.10.0 0.0.0.255
ip nat inside source list 1 interface g0/1 overload
end
copy running-config startup-config
```
#### Где выполнять проверку

- **На компьютере:** нажмите его значок → **Desktop → Command Prompt** (Командная строка). Введите приведённую ниже команду `ping ...` и нажмите Enter. `Reply from ...` означает, что ответ получен; `Request timed out` — ответа нет. Первый запрос иногда не успевает пройти, поэтому повторите проверку.
- **На маршрутизаторе или свитче:** нажмите устройство → **CLI**. Для команд `show ...` используйте режим `#`, как объяснено выше.
- **Для страницы сайта:** нажмите компьютер → **Desktop → Web Browser**, введите адрес из задания и нажмите **Go**. Адрес сайта не вводят в CLI маршрутизатора.

**Проверка:** одновременно откройте HTTP-сервер с PC1 и PC2, выполните ping. На R1: `show ip nat translations`, `show ip nat statistics`. У обоих клиентов inside global будет 203.0.113.2, а порты/идентификаторы сеансов различаются. ACL 1 здесь выбирает адреса для NAT и сама не прикрепляется к интерфейсу как фильтр. При отсутствии записей проверьте inside/outside и маршрут по умолчанию.

Справка: [Cisco — настройка NAT/PAT](https://www.cisco.com/c/en/us/support/docs/ip/network-address-translation-nat/13772-12.html).

**Сохраните работу:** Packet Tracer → **File → Save As**, выберите папку и имя `Задание-12.pkt`. Это сохраняет всю схему; команды `copy ...` выше сохраняют настройки внутри отдельных устройств.
