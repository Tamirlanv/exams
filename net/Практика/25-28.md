## Задание 25

В Wireshark захватите ICMP-трафик, определите IP-адреса отправителя и получателя и объясните последовательность обмена.

### Решение

#### Шаг 1. Подготовьте оборудование

Нужны **2 Windows-компьютера A и B** и **1 свитч**. Обычным сетевым кабелем подключите компьютер A к первому разъёму свитча, компьютер B — ко второму. Маршрутизатор не нужен. Вместо реальных компьютеров можно использовать две виртуальные машины:

#### Как соединить виртуальные компьютеры

Виртуальная машина — отдельный компьютер внутри программы VirtualBox. Здесь нужны машины с **уже установленной ОС**; установка Windows/Ubuntu не является частью сетевого задания. Реальные кабели на экране не рисуются: компьютеры с одинаковым именем внутренней сети соединяются так, будто подключены к одному свитчу.

1. Полностью выключите учебные виртуальные машины.
2. В главном окне VirtualBox выберите машину → **Settings / Настроить → Network / Сеть**.
3. Откройте **Adapter 1 / Адаптер 1** (либо другой номер из таблицы), поставьте **Enable Network Adapter / Включить сетевой адаптер**.
4. В **Attached to / Тип подключения** выберите **Internal Network / Внутренняя сеть**. В **Name / Имя** впишите имя из таблицы. В дополнительных настройках оставьте **Cable Connected / Кабель подключён** включённым.
5. Повторите для каждой строки, нажмите **OK**, затем запустите машины.

| Компьютер | Адаптер | Имя внутренней сети |
|---|---|---|
| A | 1 | exam-icmp |
| B | 1 | exam-icmp |

Ниже адреса настраиваются **внутри ОС каждой машины**. Название разъёма Linux узнайте командой `ip -br link`: обычно первый — enp0s3, второй — enp0s8; при отличии заменяйте имя в командах. [Справка Oracle по внутренним сетям](https://docs.oracle.com/en/virtualization/virtualbox/7.1/user/networkingdetails.html).

#### Где вводить команды Windows

На нужном Windows-компьютере нажмите **Win+R**, введите `cmd`, нажмите Enter — здесь выполняются `ping`, `ipconfig`, `nslookup`, `tracert`, `netstat`. Если указан **PowerShell администратора**, нажмите Пуск, найдите `PowerShell`, щёлкните правой кнопкой → **Запуск от имени администратора**. Эти команды вводят в настоящей Windows или её виртуальной машине, а не в CLI свитча.

Чтобы вручную указать IP: **Win+R → ncpa.cpl → Enter** → правой кнопкой по **Ethernet → Свойства → IP версии 4 (TCP/IPv4) → Свойства → Использовать следующий IP-адрес**. Введите указанные в задании IP, маску, шлюз и DNS, затем **ОК**. Если шлюз в задании не нужен, поле оставьте пустым. Название адаптера может отличаться от Ethernet — выберите подключённый сетевой адаптер.

#### Шаг 2. Задайте адреса

На A укажите IP **192.168.10.10**, на B — **192.168.10.20**. Маска на обоих — **255.255.255.0**. Шлюз и DNS оставьте пустыми. На A должен быть установлен Wireshark вместе с компонентом захвата Npcap.

#### Шаг 3. Разрешите ответ и запишите обмен

На B в PowerShell администратора разрешите ICMP только от A:
```powershell
New-NetFirewallRule -DisplayName "Exam ICMP from A" -Direction Inbound -Protocol ICMPv4 -IcmpType 8 -RemoteAddress 192.168.10.10 -Action Allow
```

1. Откройте Wireshark на A. На стартовом экране дважды щёлкните подключение **Ethernet**, которому назначили 192.168.10.10 — начнётся запись пакетов. Пакет — отдельная порция передаваемых данных.
2. На A в терминале выполните `ping -n 4 192.168.10.20`.
3. Нажмите красный квадрат **Stop** на верхней панели. В строку **Apply a display filter** над списком пакетов введите `icmp && ip.addr == 192.168.10.20`.
4. Щёлкните строку с `Echo (ping) request`. В средней части окна раскройте стрелками **Internet Protocol Version 4** и **Internet Control Message Protocol**. Затем сравните строку `Echo (ping) reply`. Request: источник .10, получатель .20, Type 8 Code 0. Reply: источник .20, получатель .10, Type 0 Code 0. Identifier и Sequence Number связывают запрос и ответ.
5. Сравните время пары для RTT и количество запросов/ответов. Сохраните запись: **File → Save As → icmp.pcapng**. ICMP — служебные сообщения, которыми пользуется ping; request — запрос, reply — ответ.

**Ожидаемый результат:** 4 запроса и 4 ответа при отсутствии потерь. ARP перед первым ICMP — нормальное разрешение MAC, оно скрыто фильтром icmp. Если ответов нет, проверьте firewall B и выбранный интерфейс захвата; отсутствие ответа само по себе не определяет причину.

Справка: [Wireshark — фильтры отображения](https://www.wireshark.org/docs/man-pages/wireshark-filter).

#### Шаг 3. Настройте службу имён и посмотрите запрос

DNS переводит имя `www.lab.test` в адрес `192.168.10.80`. Наличие настоящего сайта для просмотра ответа DNS здесь не требуется.

На сервере установите пакет `sudo apt install dnsmasq`, создайте `/etc/dnsmasq.d/exam.conf`:
```ini
listen-address=192.168.10.53
bind-interfaces
no-resolv
host-record=www.lab.test,192.168.10.80
```
Выполните `sudo dnsmasq --test`, `sudo systemctl restart dnsmasq`; при активном UFW разрешите DNS:
```bash
sudo ufw allow from 192.168.10.0/24 to 192.168.10.53 port 53 proto udp
sudo ufw allow from 192.168.10.0/24 to 192.168.10.53 port 53 proto tcp
``` Это локальная зона без пересылки внешних запросов.

В Wireshark нажмите красный квадрат **Stop**. В поле **Apply a display filter** над списком введите `dns && ip.addr == 192.168.10.53`.

**Разбор:** запрос A идёт с .10:случайный_порт на .53:53; ответ — с .53:53 на тот же порт клиента. Сопоставьте Transaction ID, Query Name, тип A, Response flag и Answer 192.168.10.80. nslookup может дополнительно запрашивать PTR сервера и AAAA — выделите именно пару A. Крупные ответы могут использовать TCP; в этом стенде типично UDP. DNS over HTTPS здесь не применяется, поскольку запрос явно отправлен nslookup локальному DNS.

Справка: [Wireshark — фильтры отображения](https://www.wireshark.org/docs/man-pages/wireshark-filter).

Нажмите строку запроса, в средней панели раскройте **Domain Name System (query)**. У строки ответа откройте **Domain Name System (response) → Answers**. **Transaction ID** — номер, связывающий запрос с ответом, **Query Name** — запрошенное имя. Сохраните через **File → Save As → dns.pcapng**.

#### Шаг 2. Подготовьте рабочую сеть

Настройки `ip addr` временные, до перезагрузки. Если адрес уже существует, второй раз его добавлять не нужно.

```bash
sudo ip link set enp0s3 up

**На Web** откройте терминал и выполните:

listen-address=192.168.10.53

```

Firewall DNS и Web должен разрешать соответственно DNS и HTTP; на чистых VM UFW изначально не включён.

#### Шаг 3. Создайте учебную ошибку и найдите её

Сначала на Windows PC проверьте `nslookup www.lab.test 192.168.10.53` — должен вернуться 192.168.20.80. Для примера неисправности снова откройте свойства IPv4 PC и измените **только DNS** на неправильный `192.168.10.99`. Теперь выполняйте диагностику ниже; адреса и маршруты не меняйте.

**Среда:** Windows-клиент 192.168.10.10/24 → R1 192.168.10.1 → сервер 192.168.20.80/24; DNS 192.168.10.53 обслуживает `www.lab.test`. Все IP-маршруты заранее исправны. **Учебная проблема:** доступ по IP работает, по имени — нет.

В терминале клиента:
```bat
ipconfig /all
ping 127.0.0.1
ping 192.168.10.1
ping 192.168.20.80
tracert -d 192.168.20.80
nslookup www.lab.test
nslookup www.lab.test 192.168.10.53
netstat -ano
```
Сравните настроенный DNS с .53. Если явный запрос к .53 успешен, а обычный нет, исправьте DNS клиента. В PowerShell администратора, при имени интерфейса Ethernet:
```powershell
Set-DnsClientServerAddress -InterfaceAlias "Ethernet" -ServerAddresses 192.168.10.53
Clear-DnsClientCache
Test-NetConnection 192.168.20.80 -Port 80
```
**Проверка:** обычный nslookup возвращает .80, сайт по имени открывается. На сервере `netstat -ano` должен показывать LISTENING на 80; на клиенте при активном обмене возможно ESTABLISHED. **Вывод для заданного примера:** L3-связность работала, ошибочен адрес DNS. Это ожидаемые наблюдения учебного случая, а не результаты реально выполненного захвата. Звёздочки tracert могут быть фильтрацией ICMP, поэтому оценивайте их вместе с конечной доступностью.

## Задание 28

### Решение

#### Шаг 1. Добавьте оборудование

Откройте Cisco Packet Tracer → **File → New** (Файл → Новый). Внизу слева выбирайте категорию, затем модель и щёлкайте по свободному месту рабочего поля.

- **Компьютеры: 2 шт.** Нажмите **End Devices (Конечные устройства)**, выберите **PC-PT**. Имена в инструкции: **PC-A, PC-B**.
- **Свитчи: 2 шт.** Нажмите **Network Devices → Switches (Сетевые устройства → Коммутаторы)**, выберите **2960**. Имена в инструкции: **SW1, SW2**.
- **Маршрутизаторы: 2 шт.** Нажмите **Network Devices → Routers (Маршрутизаторы)**, выберите **2911**. Имена в инструкции: **R1, R2**.

Чтобы задать имя, щёлкните по устройству → **Config → Display Name**, введите нужное имя и закройте окно. Название **свитч** и **коммутатор** означает одно и то же устройство: оно соединяет компьютеры. Маршрутизатор соединяет разные сети.

#### Шаг 2. Соедините устройства кабелями

Внизу слева нажмите **Connections** (значок молнии). Для каждой строки ниже заново выберите указанный кабель, затем щёлкните первое устройство и его разъём, после этого — второе устройство и его разъём.

1. Выберите **Copper Straight-Through (прямой медный кабель)**. Нажмите **PC-A → FastEthernet0**, затем **SW1 → FastEthernet0/1**.
2. Выберите **Copper Straight-Through (прямой медный кабель)**. Нажмите **SW1 → GigabitEthernet0/1**, затем **R1 → GigabitEthernet0/0**.
3. Выберите **Copper Cross-Over (перекрёстный медный кабель)**. Нажмите **R1 → GigabitEthernet0/1**, затем **R2 → GigabitEthernet0/1**.
4. Выберите **Copper Straight-Through (прямой медный кабель)**. Нажмите **R2 → GigabitEthernet0/0**, затем **SW2 → GigabitEthernet0/1**.
5. Выберите **Copper Straight-Through (прямой медный кабель)**. Нажмите **SW2 → FastEthernet0/1**, затем **PC-B → FastEthernet0**.

Разъём также называется **портом**. В командах `g0/0` — короткая запись GigabitEthernet0/0, `fa0/1` — FastEthernet0/1. У свитча индикатор может сначала быть оранжевым. Разъёмы маршрутизатора станут зелёными после команды `no shutdown` ниже — до настройки красный индикатор здесь допустим.

#### Шаг 3. Укажите адреса устройств

Для **каждого** компьютера или сервера из таблицы:

1. Щёлкните по его значку на схеме.
2. Откройте вкладку **Desktop** (Рабочий стол).
3. Нажмите **IP Configuration** (Настройка IP) и выберите **Static** (Вручную).
4. Перепишите значения **из строки именно этого устройства**: «IPv4» → **IPv4 Address / IP Address**, «Маска» → **Subnet Mask**, «Шлюз» → **Default Gateway**.
5. Если у шлюза написано «не нужен», оставьте поле пустым или 0.0.0.0. Остальные поля без указания не меняйте. Закройте окно — значения сохраняются автоматически.

IP-адрес — номер устройства в сети. Маска показывает границы его сети. Шлюз — адрес маршрутизатора, через который компьютер обращается в другие сети. Запись `/24` в пояснениях означает маску 255.255.255.0, `/30` — 255.255.255.252, `/29` — 255.255.255.248. В поля таблицы вводите обычные адреса и маски, без `/24`.


| Узел | IPv4 | Маска | Шлюз |
|---|---|---|---|
| PC-A | 192.168.10.10 | 255.255.255.0 | 192.168.10.1 |
| PC-B | 192.168.20.10 | 255.255.255.0 | 192.168.20.1 |

#### Что делают основные команды

`ip route` задаёт путь к другой сети: после команды идут адрес этой сети, её маска и адрес соседнего маршрутизатора, которому передать данные.

#### Как вводить команды на свитче или маршрутизаторе

1. Нажмите **устройство, названное перед блоком команд**.
2. Откройте вкладку **CLI** — это окно для ввода команд.
3. Нажмите Enter. Если появится `Would you like to enter the initial configuration dialog? [yes/no]:`, напишите `no` и нажмите Enter. При сообщении `Press RETURN to get started` ещё раз нажмите Enter. Если ещё идёт загрузка, дождитесь приглашения ввода.
4. Вводите строки блока сверху вниз, нажимая **Enter после каждой**. Копируйте только команды внутри блока. Надписи вида `Router>` или `Router#` устройство выводит само.
5. Команда `enable` открывает расширенный режим, `configure terminal` — настройку, `interface` выбирает разъём, `ip address` задаёт ему адрес, `no shutdown` включает разъём, `exit` возвращает на уровень выше, `end` завершает настройку.
6. Последняя команда `copy running-config startup-config` сохраняет настройки. На вопрос `Destination filename [startup-config]?` нажмите **Enter**, дождитесь `[OK]`.

Если ниже снова открываете то же устройство для исправления, начните с указанного блока. Команды проверки `show ...` вводятся после выхода из настройки командой `end`, когда строка заканчивается `#`; если видите `>`, сначала введите `enable`.

#### Настройте маршрутизатор R1

Нажмите **R1 → CLI**. Выполните следующие команды **на этом устройстве**, по одной строке:


```cisco
enable
configure terminal
interface g0/0
 ip address 192.168.10.1 255.255.255.0
 no shutdown
 exit
interface g0/1
 ip address 10.0.12.1 255.255.255.252
 no shutdown
 exit
ip route 192.168.20.0 255.255.255.0 10.0.12.2
end
copy running-config startup-config
```

#### Настройте маршрутизатор R2

Нажмите **R2 → CLI**. Выполните следующие команды **на этом устройстве**, по одной строке:


```cisco
enable
configure terminal
interface g0/0
 ip address 192.168.20.1 255.255.255.0
 no shutdown
 exit
interface g0/1
 ip address 10.0.12.2 255.255.255.252
 no shutdown
 exit
ip route 192.168.10.0 255.255.255.0 10.0.12.1
end
copy running-config startup-config
```

**Учебная ошибка:** на R1 вместо маршрута к 192.168.20.0/24 настроен маршрут к 192.168.30.0/24. Если получена готовая неисправная схема, сразу переходите к диагностике. Для самостоятельного примера на копии схемы нажмите **R1 → CLI**:

```cisco
enable
configure terminal
no ip route 192.168.20.0 255.255.255.0 10.0.12.2
ip route 192.168.30.0 255.255.255.0 10.0.12.2
end
```

Эти команды намеренно меняют правильный путь на ошибочный. `next-hop` означает адрес следующего маршрутизатора — здесь 10.0.12.2. Далее найдите и исправьте ошибку.

#### Где выполнять проверку

- **На компьютере:** нажмите его значок → **Desktop → Command Prompt** (Командная строка). Введите приведённую ниже команду `ping ...` и нажмите Enter. `Reply from ...` означает, что ответ получен; `Request timed out` — ответа нет. Первый запрос иногда не успевает пройти, поэтому повторите проверку.
- **На маршрутизаторе или свитче:** нажмите устройство → **CLI**. Для команд `show ...` используйте режим `#`, как объяснено выше.
- **Для страницы сайта:** нажмите компьютер → **Desktop → Web Browser**, введите адрес из задания и нажмите **Go**. Адрес сайта не вводят в CLI маршрутизатора.

**Проверка:** На PC-A в Desktop → Command Prompt выполните `ping 192.168.10.1`, затем `ping 192.168.20.10`; на PC-B — `ping 192.168.10.10`. На маршрутизаторах выполните `show ip interface brief` и `show ip route`. В строках разъёмов должно быть up/up — разъём включён и соединение работает. В списке путей C/L обозначает свои сети, S — путь, добавленный вручную к другой сети. Первый ping иногда не получает один ответ, пока устройства узнают адреса друг друга; повторите команду. Если ответов нет, проверьте шлюзы PC, маски, `no shutdown` и обратный маршрут. **Причина:** ошибочна сеть назначения статического маршрута, а не транзитный канал.

**Сохраните работу:** Packet Tracer → **File → Save As**, выберите папку и имя `Задание-28.pkt`. Это сохраняет всю схему; команды `copy ...` выше сохраняют настройки внутри отдельных устройств.
