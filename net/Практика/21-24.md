# Сетевое администрирование · практика 21–24

## Задание 21

Создайте ACL, блокирующий доступ одной заданной подсети к другой, и проверьте результат.

### Решение

**Среда:** Cisco Packet Tracer, маршрутизаторы 2911, коммутаторы 2960, PC-PT. Имена портов относятся к этим моделям. Для PC–SW и SW–R используйте Copper Straight-Through, для R–R/SW–SW — Copper Cross-Over или автоматический выбор. Дождитесь зелёных индикаторов. Команды show выполняются из привилегированного режима `#`; на запрос имени при сохранении нажмите Enter.

**Оборудование:** R1, SW1, PC10, PC20. **Схема:**

```text
PC10 Fa0 — SW1 Fa0/1 (VLAN10)
PC20 Fa0 — SW1 Fa0/3 (VLAN20)
SW1 Gi0/1 — R1 Gi0/0 (trunk VLAN10,20)
```

На PC откройте **Desktop → IP Configuration → Static**, введите:

| Узел | IPv4 | Маска | Шлюз |
|---|---|---|---|
| PC10 | 192.168.10.10 | 255.255.255.0 | 192.168.10.1 |
| PC20 | 192.168.20.10 | 255.255.255.0 | 192.168.20.1 |

**SW1 — CLI:**

```cisco
enable
configure terminal
vlan 10
 name USERS
 exit
vlan 20
 name SERVERS
 exit
interface range fa0/1 - 2
 switchport mode access
 switchport access vlan 10
 spanning-tree portfast
 exit
interface range fa0/3 - 4
 switchport mode access
 switchport access vlan 20
 spanning-tree portfast
 exit
interface g0/1
 switchport mode trunk
 switchport trunk allowed vlan 10,20
 no shutdown
 exit
end
copy running-config startup-config
```

**R1 — CLI:**

```cisco
enable
configure terminal
interface g0/0
 no ip address
 no shutdown
 exit
interface g0/0.10
 encapsulation dot1Q 10
 ip address 192.168.10.1 255.255.255.0
 exit
interface g0/0.20
 encapsulation dot1Q 20
 ip address 192.168.20.1 255.255.255.0
 exit
end
copy running-config startup-config
```

**R1 — CLI:**

```cisco
enable
configure terminal
ip access-list extended BLOCK_10_TO_20
 deny ip 192.168.10.0 0.0.0.255 192.168.20.0 0.0.0.255
 permit ip any any
 exit
interface g0/0.10
 ip access-group BLOCK_10_TO_20 in
end
copy running-config startup-config
```
**Проверка:** PC10 достигает своего шлюза 192.168.10.1, но `ping 192.168.20.10` не проходит. На R1 `show access-lists BLOCK_10_TO_20` — растёт счётчик deny; `show ip interface g0/0.10` показывает входную ACL. Важная особенность: ping из VLAN20 к PC10 также не завершится, потому что ответ PC10→PC20 запрещён. Это пакетная ACL, не правило «запретить только новые соединения» stateful firewall.

**Конкретизация политики:** заменить PC20 на Server-PT с тем же 192.168.20.10/24, шлюзом .1; включить Services → HTTP. Из VLAN10 разрешить только TCP/80 к серверу, остальной IP-трафик VLAN10 запретить.

```cisco
enable
configure terminal
ip access-list extended WEB_ONLY

interface g0/0.10
 ip access-group WEB_ONLY in
end
copy running-config startup-config
```

Обратные HTTP-ответы входят в другой интерфейс и этой входной ACL не блокируются. DNS намеренно не разрешён: в тесте используется IP. Для рабочей политики нужно отдельно разрешить конкретные инфраструктурные службы.

## Задание 23

Организуйте защищённое VPN-соединение между двумя сетевыми узлами или сегментами и проверьте передачу данных.

### Решение

**Среда:** две Ubuntu 24.04 LTS VM с WireGuard; Packet Tracer для этого решения не используется. VM находятся в одной изолированной виртуальной Ethernet-сети без NAT гипервизора. У каждой один интерфейс `enp0s3`; фактическое имя проверьте `ip -br link` и подставьте при отличии. Управляйте через консоль VM.

**Схема:** `A enp0s3 192.168.56.10/24 — виртуальный switch — B enp0s3 192.168.56.20/24`; внутри VPN A=10.8.0.1/24, B=10.8.0.2/24. Туннель защищает обмен между двумя узлами, маршрутизация чужих LAN здесь не требуется.

На каждой VM заранее установите пакет при доступном репозитории:
```bash
sudo apt update
sudo apt install wireguard
```
Назначьте лабораторный адрес (на B замените .10 на .20):
```bash
sudo ip link set enp0s3 up
sudo ip address add 192.168.56.10/24 dev enp0s3
ping -c 3 192.168.56.20
```
Если адрес уже назначен через настройки VM, повторно добавлять его не нужно. Затем **на обеих VM** создайте собственные ключи:
```bash
sudo install -d -m 700 /etc/wireguard
sudo sh -c 'umask 077; wg genkey > /etc/wireguard/private.key; wg pubkey < /etc/wireguard/private.key > /etc/wireguard/public.key'
sudo cat /etc/wireguard/public.key
```
Обменяйтесь только публичными ключами. Через `sudo nano /etc/wireguard/wg0.conf` создайте файлы ниже. Вместо меток в угловых скобках вставьте реальные значения; приватный ключ берётся из private.key только своей машины.

**A — /etc/wireguard/wg0.conf:**
```ini
[Interface]
Address = 10.8.0.1/24
ListenPort = 51820
PrivateKey = <PRIVATE_KEY_A>

[Peer]
PublicKey = <PUBLIC_KEY_B>
AllowedIPs = 10.8.0.2/32
Endpoint = 192.168.56.20:51820
PersistentKeepalive = 25
```
**B — /etc/wireguard/wg0.conf:**
```ini
[Interface]
Address = 10.8.0.2/24
ListenPort = 51820
PrivateKey = <PRIVATE_KEY_B>

[Peer]
PublicKey = <PUBLIC_KEY_A>
AllowedIPs = 10.8.0.1/32
Endpoint = 192.168.56.10:51820
PersistentKeepalive = 25
```
На обеих VM:
```bash
sudo chmod 600 /etc/wireguard/wg0.conf
sudo wg-quick up wg0
sudo wg show
ip address show wg0
```
Если UFW уже включён, на A разрешите `sudo ufw allow from 192.168.56.20 to any port 51820 proto udp`, на B — аналогично от .10. Убедитесь, что политика на wg0 допускает ICMP учебного туннеля.

**Проверка:** A: `ping -c 4 10.8.0.2`, B: `ping -c 4 10.8.0.1`; `sudo wg show` должен показать свежий latest handshake и рост transfer. Внешний захват показывает UDP/51820, а не открытый ICMP между 10.8.0.x. После успешной проверки автозапуск: `sudo systemctl enable wg-quick@wg0`. Внешние адреса, заданные командой ip, временные; для постоянного стенда закрепите их через Netplan. [Официальный WireGuard Quick Start](https://www.wireguard.com/quickstart/).

## Задание 24

**Учебная ошибка:** в Peer на A указан `AllowedIPs = 10.8.0.3/32` вместо адреса B 10.8.0.2/32. Handshake может существовать, но трафик к 10.8.0.2 не выбирает нужного peer.

1. Сравните `sudo wg show`, `ip route get 10.8.0.2` и адрес wg0 на B. Проверьте обычный ping к 192.168.56.20, правильность публичных ключей и UDP/51820.
2. Исправьте файл A: `AllowedIPs = 10.8.0.2/32`. Примените в консоли A:
```bash
sudo wg-quick down wg0
sudo wg-quick up wg0
ping -c 4 10.8.0.2
sudo wg show
```
3. Ожидается успешный ping и рост счётчиков. Если нет даже handshake, причина обычно раньше: endpoint, ключи, UDP-фильтрация; изменение маршрутов не исправит неверный ключ. В отчёте зафиксируйте обнаруженное расхождение, внесённую правку и проверку после неё.
