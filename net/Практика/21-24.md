# Сетевое администрирование · практика 21–24

## Задание 21

Создайте ACL, блокирующий доступ одной заданной подсети к другой, и проверьте результат.

### Решение

#### Шаг 1. Добавьте оборудование

Откройте Cisco Packet Tracer → **File → New** (Файл → Новый). Внизу слева выбирайте категорию, затем модель и щёлкайте по свободному месту рабочего поля.

- **Компьютеры: 2 шт.** Нажмите **End Devices (Конечные устройства)**, выберите **PC-PT**. Имена в инструкции: **PC10, PC20**.
- **Свитчи: 1 шт.** Нажмите **Network Devices → Switches (Сетевые устройства → Коммутаторы)**, выберите **2960**. Имена в инструкции: **SW1**.
- **Маршрутизаторы: 1 шт.** Нажмите **Network Devices → Routers (Маршрутизаторы)**, выберите **2911**. Имена в инструкции: **R1**.

Чтобы задать имя, щёлкните по устройству → **Config → Display Name**, введите нужное имя и закройте окно. Название **свитч** и **коммутатор** означает одно и то же устройство: оно соединяет компьютеры. Маршрутизатор соединяет разные сети.

#### Шаг 2. Соедините устройства кабелями

Внизу слева нажмите **Connections** (значок молнии). Для каждой строки ниже заново выберите указанный кабель, затем щёлкните первое устройство и его разъём, после этого — второе устройство и его разъём.

1. Выберите **Copper Straight-Through (прямой медный кабель)**. Нажмите **PC10 → FastEthernet0**, затем **SW1 → FastEthernet0/1**.
2. Выберите **Copper Straight-Through (прямой медный кабель)**. Нажмите **PC20 → FastEthernet0**, затем **SW1 → FastEthernet0/3**.
3. Выберите **Copper Straight-Through (прямой медный кабель)**. Нажмите **SW1 → GigabitEthernet0/1**, затем **R1 → GigabitEthernet0/0**.

Разъём также называется **портом**. В командах `g0/0` — короткая запись GigabitEthernet0/0, `fa0/1` — FastEthernet0/1. У свитча индикатор может сначала быть оранжевым. Разъёмы маршрутизатора станут зелёными после команды `no shutdown` ниже — до настройки красный индикатор здесь допустим.

#### Что означают слова в этом задании

VLAN — отдельная группа устройств на одном свитче. Компьютеры разных групп без маршрутизатора не обмениваются данными. `access` назначает разъём одной группе; `trunk` разрешает передавать несколько групп по одному кабелю.

ACL — список правил «разрешить/запретить». `permit` разрешает, `deny` запрещает. `in` означает проверять данные, входящие через выбранный разъём. Правила читаются сверху вниз.

#### Шаг 3. Укажите адреса устройств

Для **каждого** компьютера или сервера из таблицы:

1. Щёлкните по его значку на схеме.
2. Откройте вкладку **Desktop** (Рабочий стол).
3. Нажмите **IP Configuration** (Настройка IP) и выберите **Static** (Вручную).
4. Перепишите значения **из строки именно этого устройства**: «IPv4» → **IPv4 Address / IP Address**, «Маска» → **Subnet Mask**, «Шлюз» → **Default Gateway**.
5. Если у шлюза написано «не нужен», оставьте поле пустым или 0.0.0.0. Остальные поля без указания не меняйте. Закройте окно — значения сохраняются автоматически.

IP-адрес — номер устройства в сети. Маска показывает границы его сети. Шлюз — адрес маршрутизатора, через который компьютер обращается в другие сети. Запись `/24` в пояснениях означает маску 255.255.255.0, `/30` — 255.255.255.252, `/29` — 255.255.255.248. В поля таблицы вводите обычные адреса и маски, без `/24`.


| Узел | IPv4 | Маска | Шлюз |
|---|---|---|---|
| PC10 | 192.168.10.10 | 255.255.255.0 | 192.168.10.1 |
| PC20 | 192.168.20.10 | 255.255.255.0 | 192.168.20.1 |

#### Что делают основные команды

`interface g0/0.10` создаёт отдельную настройку для группы 10 на том же физическом разъёме. `encapsulation dot1Q 10` связывает её с VLAN 10. Второй кабель для этой группы не нужен.

#### Как вводить команды на свитче или маршрутизаторе

1. Нажмите **устройство, названное перед блоком команд**.
2. Откройте вкладку **CLI** — это окно для ввода команд.
3. Нажмите Enter. Если появится `Would you like to enter the initial configuration dialog? [yes/no]:`, напишите `no` и нажмите Enter. При сообщении `Press RETURN to get started` ещё раз нажмите Enter. Если ещё идёт загрузка, дождитесь приглашения ввода.
4. Вводите строки блока сверху вниз, нажимая **Enter после каждой**. Копируйте только команды внутри блока. Надписи вида `Router>` или `Router#` устройство выводит само.
5. Команда `enable` открывает расширенный режим, `configure terminal` — настройку, `interface` выбирает разъём, `ip address` задаёт ему адрес, `no shutdown` включает разъём, `exit` возвращает на уровень выше, `end` завершает настройку.
6. Последняя команда `copy running-config startup-config` сохраняет настройки. На вопрос `Destination filename [startup-config]?` нажмите **Enter**, дождитесь `[OK]`.

Если ниже снова открываете то же устройство для исправления, начните с указанного блока. Команды проверки `show ...` вводятся после выхода из настройки командой `end`, когда строка заканчивается `#`; если видите `>`, сначала введите `enable`.

#### Настройте свитч SW1

Нажмите **SW1 → CLI**. Выполните следующие команды **на этом устройстве**, по одной строке:


```cisco
enable
configure terminal
vlan 10
 name USERS
 exit
vlan 20
 name SERVERS
 exit
interface range fa0/1 - 2
 switchport mode access
 switchport access vlan 10
 spanning-tree portfast
 exit
interface range fa0/3 - 4
 switchport mode access
 switchport access vlan 20
 spanning-tree portfast
 exit
interface g0/1
 switchport mode trunk
 switchport trunk allowed vlan 10,20
 no shutdown
 exit
end
copy running-config startup-config
```

#### Настройте маршрутизатор R1

Нажмите **R1 → CLI**. Выполните следующие команды **на этом устройстве**, по одной строке:


```cisco
enable
configure terminal
interface g0/0
 no ip address
 no shutdown
 exit
interface g0/0.10
 encapsulation dot1Q 10
 ip address 192.168.10.1 255.255.255.0
 exit
interface g0/0.20
 encapsulation dot1Q 20
 ip address 192.168.20.1 255.255.255.0
 exit
end
copy running-config startup-config
```

#### Настройте маршрутизатор R1

Нажмите **R1 → CLI**. Выполните следующие команды **на этом устройстве**, по одной строке:


```cisco
enable
configure terminal
ip access-list extended BLOCK_10_TO_20
 deny ip 192.168.10.0 0.0.0.255 192.168.20.0 0.0.0.255
 permit ip any any
 exit
interface g0/0.10
 ip access-group BLOCK_10_TO_20 in
end
copy running-config startup-config
```
#### Где выполнять проверку

- **На компьютере:** нажмите его значок → **Desktop → Command Prompt** (Командная строка). Введите приведённую ниже команду `ping ...` и нажмите Enter. `Reply from ...` означает, что ответ получен; `Request timed out` — ответа нет. Первый запрос иногда не успевает пройти, поэтому повторите проверку.
- **На маршрутизаторе или свитче:** нажмите устройство → **CLI**. Для команд `show ...` используйте режим `#`, как объяснено выше.
- **Для страницы сайта:** нажмите компьютер → **Desktop → Web Browser**, введите адрес из задания и нажмите **Go**. Адрес сайта не вводят в CLI маршрутизатора.

**Проверка:** PC10 достигает своего шлюза 192.168.10.1, но `ping 192.168.20.10` не проходит. На R1 `show access-lists BLOCK_10_TO_20` — растёт счётчик deny; `show ip interface g0/0.10` показывает входную ACL. Важная особенность: ping из VLAN20 к PC10 также не завершится, потому что ответ PC10→PC20 запрещён. Это пакетная ACL, не правило «запретить только новые соединения» stateful firewall.

**Сохраните работу:** Packet Tracer → **File → Save As**, выберите папку и имя `Задание-21.pkt`. Это сохраняет всю схему; команды `copy ...` выше сохраняют настройки внутри отдельных устройств.

## Задание 23

Организуйте защищённое VPN-соединение между двумя сетевыми узлами или сегментами и проверьте передачу данных.

### Решение

#### Шаг 1. Подготовьте оборудование

Нужны **2 компьютера Ubuntu 24.04**, назовите их **A** и **B**. Для работы на одном ПК используйте две виртуальные машины VirtualBox. Они соединяются через один виртуальный свитч. В этой работе отдельный маршрутизатор не нужен. WireGuard создаст между компьютерами VPN — защищённое соединение.

#### Как соединить виртуальные компьютеры

Виртуальная машина — отдельный компьютер внутри программы VirtualBox. Здесь нужны машины с **уже установленной ОС**; установка Windows/Ubuntu не является частью сетевого задания. Реальные кабели на экране не рисуются: компьютеры с одинаковым именем внутренней сети соединяются так, будто подключены к одному свитчу.

1. Полностью выключите учебные виртуальные машины.
2. В главном окне VirtualBox выберите машину → **Settings / Настроить → Network / Сеть**.
3. Откройте **Adapter 1 / Адаптер 1** (либо другой номер из таблицы), поставьте **Enable Network Adapter / Включить сетевой адаптер**.
4. В **Attached to / Тип подключения** выберите **Internal Network / Внутренняя сеть**. В **Name / Имя** впишите имя из таблицы. В дополнительных настройках оставьте **Cable Connected / Кабель подключён** включённым.
5. Повторите для каждой строки, нажмите **OK**, затем запустите машины.

| Компьютер | Адаптер | Имя внутренней сети |
|---|---|---|
| A | 1 | exam-vpn |
| B | 1 | exam-vpn |

Ниже адреса настраиваются **внутри ОС каждой машины**. Название разъёма Linux узнайте командой `ip -br link`: обычно первый — enp0s3, второй — enp0s8; при отличии заменяйте имя в командах. [Справка Oracle по внутренним сетям](https://docs.oracle.com/en/virtualization/virtualbox/7.1/user/networkingdetails.html).

#### Где вводить команды Linux

Все команды этого раздела вводятся **внутри нужного компьютера Ubuntu**, не в PowerShell Windows и не в окне Cisco Packet Tracer. Откройте окно этой виртуальной машины, войдите в Ubuntu. В Ubuntu с рабочим столом нажмите **Ctrl+Alt+T** — откроется Терминал; в Ubuntu Server командная строка появляется после входа.

#### Шаг 2. Настройте адреса, ключи и защищённое соединение

#### Шаг 1. Подготовьте оборудование

Нужны **2 компьютера Ubuntu 24.04**, назовите их **A** и **B**. Для работы на одном ПК используйте две виртуальные машины VirtualBox. Они соединяются через один виртуальный свитч. В этой работе отдельный маршрутизатор не нужен. WireGuard создаст между компьютерами VPN — защищённое соединение.

#### Как соединить виртуальные компьютеры

Виртуальная машина — отдельный компьютер внутри программы VirtualBox. Здесь нужны машины с **уже установленной ОС**; установка Windows/Ubuntu не является частью сетевого задания. Реальные кабели на экране не рисуются: компьютеры с одинаковым именем внутренней сети соединяются так, будто подключены к одному свитчу.

1. Полностью выключите учебные виртуальные машины.
2. В главном окне VirtualBox выберите машину → **Settings / Настроить → Network / Сеть**.
3. Откройте **Adapter 1 / Адаптер 1** (либо другой номер из таблицы), поставьте **Enable Network Adapter / Включить сетевой адаптер**.
4. В **Attached to / Тип подключения** выберите **Internal Network / Внутренняя сеть**. В **Name / Имя** впишите имя из таблицы. В дополнительных настройках оставьте **Cable Connected / Кабель подключён** включённым.
5. Повторите для каждой строки, нажмите **OK**, затем запустите машины.

| Компьютер | Адаптер | Имя внутренней сети |
|---|---|---|
| A | 1 | exam-vpn |
| B | 1 | exam-vpn |
