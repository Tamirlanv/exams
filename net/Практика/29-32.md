# Сетевое администрирование · практика 29–32

## Задание 29

В сети с некорректной выдачей адресов DHCP найдите ошибку в пуле, шлюзе или DNS-параметрах и исправьте её.

### Решение

#### Шаг 1. Добавьте оборудование

Откройте Cisco Packet Tracer → **File → New** (Файл → Новый). Внизу слева выбирайте категорию, затем модель и щёлкайте по свободному месту рабочего поля.

- **Компьютеры: 1 шт.** Нажмите **End Devices (Конечные устройства)**, выберите **PC-PT**. Имена в инструкции: **PC**.
- **Свитчи: 1 шт.** Нажмите **Network Devices → Switches (Сетевые устройства → Коммутаторы)**, выберите **2960**. Имена в инструкции: **SW1**.
- **Маршрутизаторы: 1 шт.** Нажмите **Network Devices → Routers (Маршрутизаторы)**, выберите **2911**. Имена в инструкции: **R1**.
- **Серверы: 1 шт.** Нажмите **End Devices (Конечные устройства)**, выберите **Server-PT**. Имена в инструкции: **Server**.

Чтобы задать имя, щёлкните по устройству → **Config → Display Name**, введите нужное имя и закройте окно. Название **свитч** и **коммутатор** означает одно и то же устройство: оно соединяет компьютеры. Маршрутизатор соединяет разные сети.

#### Шаг 2. Соедините устройства кабелями

Внизу слева нажмите **Connections** (значок молнии). Для каждой строки ниже заново выберите указанный кабель, затем щёлкните первое устройство и его разъём, после этого — второе устройство и его разъём.

1. Выберите **Copper Straight-Through (прямой медный кабель)**. Нажмите **PC → FastEthernet0**, затем **SW1 → FastEthernet0/1**.
2. Выберите **Copper Straight-Through (прямой медный кабель)**. Нажмите **Server → FastEthernet0**, затем **SW1 → FastEthernet0/2**.
3. Выберите **Copper Straight-Through (прямой медный кабель)**. Нажмите **SW1 → GigabitEthernet0/1**, затем **R1 → GigabitEthernet0/0**.

Разъём также называется **портом**. В командах `g0/0` — короткая запись GigabitEthernet0/0, `fa0/1` — FastEthernet0/1. У свитча индикатор может сначала быть оранжевым. Разъёмы маршрутизатора станут зелёными после команды `no shutdown` ниже — до настройки красный индикатор здесь допустим.

#### Что означают слова в этом задании

DHCP автоматически выдаёт компьютеру IP-адрес и другие настройки. «Пул» — набор адресов, которые разрешено выдавать. «Аренда» — выданный конкретному компьютеру адрес на определённое время.

#### Шаг 3. Настройте сервер

Нажмите сервер **Server → Desktop → IP Configuration → Static**. Введите **IP Address: 192.168.10.53**, **Subnet Mask: 255.255.255.0**, **Default Gateway: 192.168.10.1**.

Откройте **Services → DNS**, выберите **On**. В поле **Name** введите `server.lab.test`, в **Type** оставьте `A Record`, в **Address** введите адрес этого сервера. Нажмите **Add**. DNS — служба, которая переводит имя сайта в IP-адрес.

#### Что делают основные команды

`ip dhcp pool` создаёт набор выдаваемых адресов. `default-router` сообщает компьютерам адрес шлюза, `dns-server` — адрес службы имён. `excluded-address` исключает адреса, которые нельзя выдавать автоматически.

#### Как вводить команды на свитче или маршрутизаторе

1. Нажмите **устройство, названное перед блоком команд**.
2. Откройте вкладку **CLI** — это окно для ввода команд.
3. Нажмите Enter. Если появится `Would you like to enter the initial configuration dialog? [yes/no]:`, напишите `no` и нажмите Enter. При сообщении `Press RETURN to get started` ещё раз нажмите Enter. Если ещё идёт загрузка, дождитесь приглашения ввода.
4. Вводите строки блока сверху вниз, нажимая **Enter после каждой**. Копируйте только команды внутри блока. Надписи вида `Router>` или `Router#` устройство выводит само.
5. Команда `enable` открывает расширенный режим, `configure terminal` — настройку, `interface` выбирает разъём, `ip address` задаёт ему адрес, `no shutdown` включает разъём, `exit` возвращает на уровень выше, `end` завершает настройку.
6. Последняя команда `copy running-config startup-config` сохраняет настройки. На вопрос `Destination filename [startup-config]?` нажмите **Enter**, дождитесь `[OK]`.

Если ниже снова открываете то же устройство для исправления, начните с указанного блока. Команды проверки `show ...` вводятся после выхода из настройки командой `end`, когда строка заканчивается `#`; если видите `>`, сначала введите `enable`.

#### Настройте маршрутизатор R1

Нажмите **R1 → CLI**. Выполните следующие команды **на этом устройстве**, по одной строке:


```cisco
enable
configure terminal
interface g0/0
 ip address 192.168.10.1 255.255.255.0
 no shutdown
 exit
ip dhcp excluded-address 192.168.10.1 192.168.10.99
ip dhcp pool LAN10
 network 192.168.10.0 255.255.255.0
 default-router 192.168.10.1
 dns-server 192.168.10.53
 exit
end
copy running-config startup-config
```
Нажмите **PC → Desktop → IP Configuration → DHCP** и дождитесь появления адреса. Закройте это окно, откройте **Desktop → Command Prompt** и по очереди выполните `ipconfig /all`, `ping 192.168.10.1`, `nslookup server.lab.test`. Если модель PC не поддерживает /all, посмотрите поля в IP Configuration.

#### Где выполнять проверку

- **На компьютере:** нажмите его значок → **Desktop → Command Prompt** (Командная строка). Введите приведённую ниже команду `ping ...` и нажмите Enter. `Reply from ...` означает, что ответ получен; `Request timed out` — ответа нет. Первый запрос иногда не успевает пройти, поэтому повторите проверку.
- **На маршрутизаторе или свитче:** нажмите устройство → **CLI**. Для команд `show ...` используйте режим `#`, как объяснено выше.
- **Для страницы сайта:** нажмите компьютер → **Desktop → Web Browser**, введите адрес из задания и нажмите **Go**. Адрес сайта не вводят в CLI маршрутизатора.

**Проверка:** на R1 `show ip dhcp binding`, `show ip dhcp pool`. Адрес клиента из .100–.254, маска /24, шлюз .1, DNS .53. DNS-сервер находится вне выдаваемого диапазона. Если аренда отсутствует, проверьте порт, VLAN, интерфейс R1 и свободные адреса пула.
**Учебная неисправность:** в пуле LAN10 указаны default-router 192.168.10.254 и dns-server 192.168.10.99; таких служб по этим адресам нет. Сам клиент при этом может получить нормальный адрес.

Сопоставьте `ipconfig /all` клиента, `show running-config` и `show ip dhcp binding` маршрутизатора с планом адресации. Исправьте R1:

#### Настройте маршрутизатор R1

Нажмите **R1 → CLI**. Выполните следующие команды **на этом устройстве**, по одной строке:


```cisco
enable
configure terminal
ip dhcp pool LAN10
 no default-router
 no dns-server
 default-router 192.168.10.1
 dns-server 192.168.10.53
end
copy running-config startup-config
```
На клиенте `ipconfig /release`, `ipconfig /renew` либо переключите Static → DHCP в Packet Tracer. Повторите проверку параметров, ping шлюза и nslookup server.lab.test. Исправление пула само по себе не обязано немедленно обновить уже выданную аренду.

**Сохраните работу:** Packet Tracer → **File → Save As**, выберите папку и имя `Задание-29.pkt`. Это сохраняет всю схему; команды `copy ...` выше сохраняют настройки внутри отдельных устройств.

## Задание 31

Настройте мониторинг состояния сетевого устройства или службы и определите признаки недоступности или сбоя.

### Решение

#### Шаг 1. Подготовьте два компьютера

Нужны **2 Ubuntu-компьютера**: **Monitor** (проверяет сеть) и **Web** (сайт). Подключите их кабелями к одному свитчу: Monitor к первому разъёму, Web ко второму. Маршрутизатор не нужен. В VirtualBox:

#### Как соединить виртуальные компьютеры

Виртуальная машина — отдельный компьютер внутри программы VirtualBox. Здесь нужны машины с **уже установленной ОС**; установка Windows/Ubuntu не является частью сетевого задания. Реальные кабели на экране не рисуются: компьютеры с одинаковым именем внутренней сети соединяются так, будто подключены к одному свитчу.

1. Полностью выключите учебные виртуальные машины.
2. В главном окне VirtualBox выберите машину → **Settings / Настроить → Network / Сеть**.
3. Откройте **Adapter 1 / Адаптер 1** (либо другой номер из таблицы), поставьте **Enable Network Adapter / Включить сетевой адаптер**.
4. В **Attached to / Тип подключения** выберите **Internal Network / Внутренняя сеть**. В **Name / Имя** впишите имя из таблицы. В дополнительных настройках оставьте **Cable Connected / Кабель подключён** включённым.
5. Повторите для каждой строки, нажмите **OK**, затем запустите машины.

| Компьютер | Адаптер | Имя внутренней сети |
|---|---|---|
| Monitor | 1 | exam-monitor |
| Web | 1 | exam-monitor |

Ниже адреса настраиваются **внутри ОС каждой машины**. Название разъёма Linux узнайте командой `ip -br link`: обычно первый — enp0s3, второй — enp0s8; при отличии заменяйте имя в командах. [Справка Oracle по внутренним сетям](https://docs.oracle.com/en/virtualization/virtualbox/7.1/user/networkingdetails.html).

#### Где вводить команды Linux

Все команды этого раздела вводятся **внутри нужного компьютера Ubuntu**, не в PowerShell Windows и не в окне Cisco Packet Tracer. Откройте окно этой виртуальной машины, войдите в Ubuntu. В Ubuntu с рабочим столом нажмите **Ctrl+Alt+T** — откроется Терминал; в Ubuntu Server командная строка появляется после входа.

Вводите одну строку за другой и нажимайте Enter. `sudo` означает выполнить действие с правами администратора: введите пароль Ubuntu; символы пароля при вводе не отображаются — это нормально. `apt install` устанавливает программу и требует доступа к репозиторию. Установите программы до отключения Интернета в учебной сети.

Если сказано «создайте файл», откройте его командой `sudo nano /полный/путь/к/файлу`, вставьте приведённый текст, нажмите **Ctrl+O → Enter** для сохранения, затем **Ctrl+X** для выхода. Блоки `ini` и `yaml` — **содержимое файлов**, их не вводят построчно как команды. Строки в блоке `bash` — команды терминала. Для обычного файла в домашней папке достаточно `nano имя-файла`.

#### Шаг 2. Назначьте адреса

На Monitor выполните `sudo ip link set enp0s3 up`, затем `sudo ip addr add 192.168.10.10/24 dev enp0s3`. На Web аналогично задайте `192.168.10.80/24`. Если адреса уже настроены, повторно добавлять их не нужно. На Monitor установите curl командой `sudo apt install curl`, на Web — `sudo apt install nginx`; доступ к установке пакетов подготовьте заранее.

#### Шаг 3. Запустите сайт и программу проверки

**Среда:** Ubuntu-монитор 192.168.10.10 и Linux-веб-сервер 192.168.10.80 в одной /24 через switch. На сервере установите `nginx`, запустите `sudo systemctl enable --now nginx`, разрешите TCP/80 от монитора. На мониторе установите curl.

На Monitor откройте терминал, выполните **`nano monitor.sh`**, вставьте весь блок ниже. Нажмите **Ctrl+O → Enter → Ctrl+X**. Затем в терминале выполните **`bash monitor.sh`**:
```bash
#!/usr/bin/env bash
target=192.168.10.80
for attempt in {1..12}; do
  stamp=$(date -Is)
  if ping -c 1 -W 1 "$target" >/dev/null 2>&1; then host=UP; else host=DOWN; fi
  if curl --fail --silent --show-error --max-time 3 "http://$target/" >/dev/null 2>&1; then
    http=UP
  else
    http=DOWN
  fi
  printf '%s host=%s http=%s
' "$stamp" "$host" "$http" | tee -a monitor.log
  sleep 5
done
```
**Проверка сбоя:** в отдельной консоли учебного сервера выполните `sudo systemctl stop nginx`: ожидается host=UP, http=DOWN. Восстановите `sudo systemctl start nginx`, следующая проверка должна показать UP/UP. Если отключить виртуальный сетевой адаптер, обычно оба статуса DOWN. ICMP может фильтроваться, поэтому доступность службы оценивают отдельно. Для постоянного мониторинга задают порог нескольких ошибок подряд, уведомление и контроль восстановления.

`host=UP` означает «компьютер отвечает», `http=UP` — «сайт отвечает», `DOWN` — ответа нет. Для имитации неисправности переключитесь **в окно Web**, откройте второй терминал и остановите nginx, как указано выше. Результаты смотрите **в окне Monitor**.

## Задание 32

Проанализируйте журнал сетевых событий и выделите записи, указывающие на ошибку, отказ службы или подозрительную активность.

Для разбора готовых строк ниже оборудование соединять не нужно: это задание на чтение журнала. Если требуется посмотреть настоящий журнал, нужен **1 Ubuntu-компьютер** со службами SSH или nginx. Журнал — список событий, которые система записывает автоматически.

#### Где вводить команды Linux

Все команды этого раздела вводятся **внутри нужного компьютера Ubuntu**, не в PowerShell Windows и не в окне Cisco Packet Tracer. Откройте окно этой виртуальной машины, войдите в Ubuntu. В Ubuntu с рабочим столом нажмите **Ctrl+Alt+T** — откроется Терминал; в Ubuntu Server командная строка появляется после входа.

Вводите одну строку за другой и нажимайте Enter. `sudo` означает выполнить действие с правами администратора: введите пароль Ubuntu; символы пароля при вводе не отображаются — это нормально. `apt install` устанавливает программу и требует доступа к репозиторию. Установите программы до отключения Интернета в учебной сети.

Если сказано «создайте файл», откройте его командой `sudo nano /полный/путь/к/файлу`, вставьте приведённый текст, нажмите **Ctrl+O → Enter** для сохранения, затем **Ctrl+X** для выхода. Блоки `ini` и `yaml` — **содержимое файлов**, их не вводят построчно как команды. Строки в блоке `bash` — команды терминала. Для обычного файла в домашней папке достаточно `nano имя-файла`.

#### Как выполнить

1. Прочитайте учебные строки ниже. Найдите время, название программы и сообщение об ошибке.
2. Если используете свой Ubuntu, откройте терминал и выполните приведённые команды `journalctl` — они показывают записи, а не меняют сеть.
3. Выпишите: «время → что случилось → что проверить администратору». Сравните с готовым разбором после команд.

**Среда:** Ubuntu-сервер SSH, журнал systemd; отдельный switch не обязателен. Схема: `клиенты → сеть → SSH-сервер → journal/syslog`. В условии конкретный журнал не дан, поэтому ниже используется учебный набор событий.

```text
10:00:00 kernel: enp0s3: Link is Down
10:00:05 systemd: nginx.service: Failed with result 'exit-code'
10:01:01 sshd: Failed password for invalid user admin from 192.168.10.50
10:01:03 sshd: Failed password for invalid user admin from 192.168.10.50
10:01:05 sshd: Failed password for invalid user admin from 192.168.10.50
10:02:00 sshd: Accepted publickey for operator from 192.168.10.10
```
Для реального сбора на учебной Ubuntu:
```bash
sudo journalctl --since '-30 min' -p warning --no-pager
sudo journalctl -u ssh --since '-30 min' --no-pager
sudo journalctl -u nginx --since '-30 min' --no-pager
ip -s link show enp0s3
sudo systemctl status nginx --no-pager
timedatectl status
```
**Анализ:** Link Down указывает на потерю физического/виртуального канала; Failed nginx — на отказ службы, его причину ищут в соседних записях. Повторные Failed password одного источника — возможный перебор или ошибочный клиент; требуется сверить контекст. Accepted publickey — успешный вход, легитимность подтверждают владельцем и расписанием. Сохраните журнал, проверьте NTP и не считайте последующее успешное событие доказательством связи с предыдущими ошибками без дополнительных данных.
