## Задание 13

Для сети 192.168.10.0/24 выполните деление на четыре равные подсети и укажите адрес сети, диапазон узлов и broadcast каждой подсети.

### Решение

**Среда:** расчёт IPv4; оборудование не требуется. Четыре подсети означают заимствование 2 бит: /24 + 2 = /26. Маска 255.255.255.192, шаг 256−192=64. В каждой подсети 64 адреса, из них 62 обычных адреса узлов.

| Сеть | Диапазон узлов | Broadcast |
|---|---|---|
| 192.168.10.0/26 | 192.168.10.1–192.168.10.62 | 192.168.10.63 |
| 192.168.10.64/26 | 192.168.10.65–192.168.10.126 | 192.168.10.127 |
| 192.168.10.128/26 | 192.168.10.129–192.168.10.190 | 192.168.10.191 |
| 192.168.10.192/26 | 192.168.10.193–192.168.10.254 | 192.168.10.255 |

**Проверка в Python 3:**
```python
import ipaddress
for subnet in ipaddress.ip_network('192.168.10.0/24').subnets(new_prefix=26):
    hosts = list(subnet.hosts())
    print(subnet, subnet.netmask, hosts[0], hosts[-1], subnet.broadcast_address)
```
Подсети не пересекаются и вместе покрывают исходные 256 адресов. Если подключать их к маршрутизатору, каждой нужен собственный L3-интерфейс/VLAN и шлюз из её диапазона.

## Задание 14

Для сети 172.16.20.0/26 определите адрес сети, допустимый диапазон адресов узлов и широковещательный адрес.

### Решение

**Среда:** расчёт, без оборудования. /26 означает 26 бит сети и 6 бит узла. Маска 255.255.255.192, размер блока 64. Последний октет 0 уже кратен размеру блока, поэтому задан именно адрес сети.

- Сеть: **172.16.20.0/26**.
- Первый узел: **172.16.20.1**.
- Последний узел: **172.16.20.62**.
- Broadcast: **172.16.20.63**.
- Всего адресов: 64, доступно узлам: 62; возможный шлюз: .1.

Проверка Python 3:
```python
import ipaddress
n = ipaddress.ip_network('172.16.20.0/26')
print(n.network_address, n.netmask, n.broadcast_address, n.num_addresses)
print(list(n.hosts())[0], list(n.hosts())[-1])
```
Адрес .64 относится уже к следующей подсети и не может использоваться узлом этой сети.

## Задание 15

Назначьте IPv6-адреса двум сетевым узлам и маршрутизатору, затем проверьте IPv6-связность.

### Решение

**Среда:** Cisco Packet Tracer, маршрутизаторы 2911, коммутаторы 2960, PC-PT. Имена портов относятся к этим моделям. Для PC–SW и SW–R используйте Copper Straight-Through, для R–R/SW–SW — Copper Cross-Over или автоматический выбор. Дождитесь зелёных индикаторов. Команды show выполняются из привилегированного режима `#`; на запрос имени при сохранении нажмите Enter.

**Схема:** PC1 — SW1 — R1 Gi0/0, R1 Gi0/1 — SW2 — PC2. На каждом SW PC подключён к Fa0/1, R — к Gi0/1.

**R1 — CLI:**

```cisco
enable
configure terminal
ipv6 unicast-routing
interface g0/0
 ipv6 address 2001:DB8:10::1/64
 ipv6 address FE80::1 link-local
 no shutdown
 exit
interface g0/1
 ipv6 address 2001:DB8:20::1/64
 ipv6 address FE80::1 link-local
 no shutdown
end
copy running-config startup-config
```
На PC1 в IPv6 Configuration задайте `2001:db8:10::10/64`, на PC2 — `2001:db8:20::10/64`; IPv6-шлюз на обоих — `fe80::1`. Одинаковый link-local допустим на разных каналах.

**Проверка:** на R1 `show ipv6 interface brief`, `show ipv6 route`; на PC1 `ping 2001:db8:20::10`, на PC2 `ping 2001:db8:10::10`. В таблице R1 две непосредственно подключённые /64; динамический протокол здесь не требуется. Не переносите IPv4 broadcast в IPv6 — его нет.

## Задание 16

Настройте статический маршрут между двумя удалёнными локальными сетями и проверьте прохождение трафика.

### Решение

**Среда:** Cisco Packet Tracer, маршрутизаторы 2911, коммутаторы 2960, PC-PT. Имена портов относятся к этим моделям. Для PC–SW и SW–R используйте Copper Straight-Through, для R–R/SW–SW — Copper Cross-Over или автоматический выбор. Дождитесь зелёных индикаторов. Команды show выполняются из привилегированного режима `#`; на запрос имени при сохранении нажмите Enter.

**Оборудование:** 2 R, 2 SW, 2 PC.

**Подключение:**

```text
PC-A Fa0 — SW1 Fa0/1; SW1 Gi0/1 — R1 Gi0/0
R1 Gi0/1 (10.0.12.1/30) — R2 Gi0/1 (10.0.12.2/30)
R2 Gi0/0 — SW2 Gi0/1; SW2 Fa0/1 — PC-B Fa0
```

На PC откройте **Desktop → IP Configuration → Static**, введите:

| Узел | IPv4 | Маска | Шлюз |
|---|---|---|---|
| PC-A | 192.168.10.10 | 255.255.255.0 | 192.168.10.1 |
| PC-B | 192.168.20.10 | 255.255.255.0 | 192.168.20.1 |

**R1 — CLI:**

```cisco
enable
configure terminal
interface g0/0
 ip address 192.168.10.1 255.255.255.0
 no shutdown
 exit
interface g0/1
 ip address 10.0.12.1 255.255.255.252
 no shutdown
 exit
ip route 192.168.20.0 255.255.255.0 10.0.12.2
end
copy running-config startup-config
```

**R2 — CLI:**

```cisco
enable
configure terminal
interface g0/0
 ip address 192.168.20.1 255.255.255.0
 no shutdown
 exit
interface g0/1
 ip address 10.0.12.2 255.255.255.252
 no shutdown
 exit
ip route 192.168.10.0 255.255.255.0 10.0.12.1
end
copy running-config startup-config
```

**Проверка статических маршрутов:** На PC-A в Desktop → Command Prompt выполните `ping 192.168.10.1`, затем `ping 192.168.20.10`; на PC-B — `ping 192.168.10.10`. На маршрутизаторах выполните `show ip interface brief` и `show ip route`. Ожидаются up/up и маршруты C/L к локальным сетям, S к удалённой. Первый ping может потерять пакет при ARP; повторите. Если ответов нет, проверьте шлюзы PC, маски, `no shutdown` и обратный маршрут. Запись `S 192.168.20.0/24 via 10.0.12.2` на R1 означает конкретный путь в удалённую LAN, а не адрес локального интерфейса.
