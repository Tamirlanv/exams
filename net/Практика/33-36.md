# Сетевое администрирование · практика 33–36

## Задание 33

Составьте набор правил брандмауэра для разрешения необходимого трафика и блокирования нежелательных соединений.

### Решение

#### Шаг 1. Подготовьте оборудование

Нужны **4 Ubuntu-компьютера**: **Admin** — разрешённый администратор, **Other** — обычный пользователь для проверки запрета, **Router** — маршрутизатор с двумя картами, **Server** — защищаемый сервер. До изоляции сети установите на Server `sudo apt install ufw nginx openssh-server`, на Admin и Other — `sudo apt install curl openssh-client`.

Соединение: **Admin и Other к первому свитчу; свитч к Router; второй разъём Router ко второму свитчу; Server ко второму свитчу**. В VirtualBox:

#### Как соединить виртуальные компьютеры

Виртуальная машина — отдельный компьютер внутри программы VirtualBox. Здесь нужны машины с **уже установленной ОС**; установка Windows/Ubuntu не является частью сетевого задания. Реальные кабели на экране не рисуются: компьютеры с одинаковым именем внутренней сети соединяются так, будто подключены к одному свитчу.

1. Полностью выключите учебные виртуальные машины.
2. В главном окне VirtualBox выберите машину → **Settings / Настроить → Network / Сеть**.
3. Откройте **Adapter 1 / Адаптер 1** (либо другой номер из таблицы), поставьте **Enable Network Adapter / Включить сетевой адаптер**.
4. В **Attached to / Тип подключения** выберите **Internal Network / Внутренняя сеть**. В **Name / Имя** впишите имя из таблицы. В дополнительных настройках оставьте **Cable Connected / Кабель подключён** включённым.
5. Повторите для каждой строки, нажмите **OK**, затем запустите машины.

| Компьютер | Адаптер | Имя внутренней сети |
|---|---|---|
| Admin | 1 | exam-clients |
| Other | 1 | exam-clients |
| Router | 1 | exam-clients |
| Router | 2 | exam-server |
| Server | 1 | exam-server |

Ниже адреса настраиваются **внутри ОС каждой машины**. Название разъёма Linux узнайте командой `ip -br link`: обычно первый — enp0s3, второй — enp0s8; при отличии заменяйте имя в командах. [Справка Oracle по внутренним сетям](https://docs.oracle.com/en/virtualization/virtualbox/7.1/user/networkingdetails.html).

#### Где вводить команды Linux

Все команды этого раздела вводятся **внутри нужного компьютера Ubuntu**, не в PowerShell Windows и не в окне Cisco Packet Tracer. Откройте окно этой виртуальной машины, войдите в Ubuntu. В Ubuntu с рабочим столом нажмите **Ctrl+Alt+T** — откроется Терминал; в Ubuntu Server командная строка появляется после входа.

Вводите одну строку за другой и нажимайте Enter. `sudo` означает выполнить действие с правами администратора: введите пароль Ubuntu; символы пароля при вводе не отображаются — это нормально. `apt install` устанавливает программу и требует доступа к репозиторию. Установите программы до отключения Интернета в учебной сети.

Если сказано «создайте файл», откройте его командой `sudo nano /полный/путь/к/файлу`, вставьте приведённый текст, нажмите **Ctrl+O → Enter** для сохранения, затем **Ctrl+X** для выхода. Блоки `ini` и `yaml` — **содержимое файлов**, их не вводят построчно как команды. Строки в блоке `bash` — команды терминала. Для обычного файла в домашней папке достаточно `nano имя-файла`.

#### Шаг 2. Задайте адреса

**На Router (Ubuntu)** откройте терминал. Здесь первая карта соединена с компьютерами, вторая — с другой сетью:

```bash
sudo ip link set enp0s3 up
sudo ip link set enp0s8 up
sudo ip addr add 192.168.10.1/24 dev enp0s3
sudo ip addr add 192.168.20.1/24 dev enp0s8
sudo sysctl -w net.ipv4.ip_forward=1
```

Последняя команда разрешает Ubuntu передавать данные между двумя картами — теперь она работает как маршрутизатор. Это чистый учебный маршрутизатор без включённого UFW и других ограничивающих правил. Настройки `ip addr` временные, до перезагрузки. Если адрес уже существует, второй раз его добавлять не нужно.

**На Admin** откройте терминал и выполните:

```bash
sudo ip link set enp0s3 up
sudo ip addr add 192.168.10.10/24 dev enp0s3
sudo ip route replace default via 192.168.10.1
```

**На Other** откройте терминал и выполните:

```bash
sudo ip link set enp0s3 up
sudo ip addr add 192.168.10.11/24 dev enp0s3
sudo ip route replace default via 192.168.10.1
```

**На Server** откройте терминал и выполните:

```bash
sudo ip link set enp0s3 up
sudo ip addr add 192.168.20.80/24 dev enp0s3
sudo ip route replace default via 192.168.20.1
```

На Server выполните `sudo systemctl start nginx`, затем `sudo systemctl start ssh`. Команда `whoami` покажет имя пользователя Server — запишите его для проверки входа.

#### Шаг 3. Ограничьте подключения к серверу

Следующие команды UFW вводите **только на Server**, не на Router. Firewall (брандмауэр) — программа, которая пропускает разрешённые соединения и блокирует остальные. TCP/22 — удалённая командная строка SSH, TCP/80 — обычный сайт HTTP, TCP/443 — защищённый сайт HTTPS.

**Среда:** Ubuntu 24.04, UFW, сервер 192.168.20.80/24, администратор 192.168.10.10 через маршрутизатор. Nginx и SSH установлены, маршрутизация уже работает. Правила задаются на сервере, через его локальную консоль. **Политика:** SSH только от администратора, HTTP/HTTPS от сети 192.168.10.0/24, остальные входящие запрещены, исходящие разрешены.

Сначала проверьте `sudo ufw status numbered` и удалите только старые правила учебного стенда, противоречащие этой политике, по их номерам. Затем:
```bash
sudo ufw default deny incoming
sudo ufw default allow outgoing
sudo ufw allow from 192.168.10.10 to any port 22 proto tcp
sudo ufw allow from 192.168.10.0/24 to any port 80 proto tcp
sudo ufw allow from 192.168.10.0/24 to any port 443 proto tcp
sudo ufw logging on
sudo ufw enable
sudo ufw status verbose
```
**Проверка:** с администратора `ssh user@192.168.20.80`, с клиента этой сети `curl http://192.168.20.80`; с другого источника SSH не проходит. Правило 443 лишь разрешает HTTPS: для успешного запроса сервер должен реально слушать 443 и иметь сертификат. UFW автоматически учитывает established/related и имеет стандартные системные правила, в том числе для части ICMP; политика выше относится к новым входящим службам. [Документация Ubuntu UFW](https://ubuntu.com/server/docs/firewalls/).

#### Шаг 4. Проверьте результат с разных компьютеров

1. На **Admin** откройте терминал → `ssh ИМЯ_ПОЛЬЗОВАТЕЛЯ@192.168.20.80`. Вместо ИМЯ_ПОЛЬЗОВАТЕЛЯ введите результат `whoami` с Server. При первом подключении подтвердите ключ сервера после сверки, затем введите пароль этой учётной записи. Вход должен работать; для выхода — `exit`.
2. На **Other** попробуйте ту же команду — соединение должно блокироваться.
3. На **Admin** и **Other** выполните `curl http://192.168.20.80`: оба получают HTML-код сайта.
4. На **Server** выполните `sudo ufw status verbose` — здесь видны действующие правила. Разрешённый порт сам по себе не запускает программу: поэтому HTTP и SSH запущены отдельно.

## Задание 34

По заданному набору сетевых событий определите, какие из них должны быть выявлены IDS, и предложите действие администратора.

### Решение

#### Что понадобится

В этом задании требуется **оценить события и предложить действия**, поэтому собирать сеть и запускать атаки не нужно. Используйте таблицу ниже. IDS — программа-наблюдатель, которая сообщает о подозрительном поведении. Suricata — один из вариантов такой программы.

#### Как выполнить основную часть

1. Прочитайте каждое событие в первом столбце.
2. Во втором столбце указано, почему оно подозрительно или может быть нормальным.
3. В третьем — что сделать администратору. Перенесите эти выводы в ответ.
4. Команды ниже нужны только если преподаватель предоставил компьютер **с уже установленной и настроенной Suricata**. Они не устанавливают IDS с нуля.

#### Где вводить команды Linux

Все команды этого раздела вводятся **внутри нужного компьютера Ubuntu**, не в PowerShell Windows и не в окне Cisco Packet Tracer. Откройте окно этой виртуальной машины, войдите в Ubuntu. В Ubuntu с рабочим столом нажмите **Ctrl+Alt+T** — откроется Терминал; в Ubuntu Server командная строка появляется после входа.

Вводите одну строку за другой и нажимайте Enter. `sudo` означает выполнить действие с правами администратора: введите пароль Ubuntu; символы пароля при вводе не отображаются — это нормально. `apt install` устанавливает программу и требует доступа к репозиторию. Установите программы до отключения Интернета в учебной сети.

Если сказано «создайте файл», откройте его командой `sudo nano /полный/путь/к/файлу`, вставьте приведённый текст, нажмите **Ctrl+O → Enter** для сохранения, затем **Ctrl+X** для выхода. Блоки `ini` и `yaml` — **содержимое файлов**, их не вводят построчно как команды. Строки в блоке `bash` — команды терминала. Для обычного файла в домашней папке достаточно `nano имя-файла`.

**Среда и схема:** `клиенты — SW с SPAN — серверы`; копия проходящих через свитч данных поступает на интерфейс сетевой IDS. Для учебной Ubuntu с Suricata в роли IDS компьютер-наблюдатель не ставят в разрыв между клиентами и сервером. Набор событий в условии отсутствует, поэтому задан следующий пример:

| Событие | Оценка IDS | Действие администратора |
|---|---|---|
| Один клиент обращается к десяткам портов за секунды | Возможное сканирование | Проверить разрешённые сканеры, источник и масштаб |
| Сотни неудачных входов SSH | Возможный перебор; нужны журналы HIDS/SIEM | Проверить учётную запись, ограничить источник по процедуре |
| Сигнатура известного эксплойта в HTTP | Высокоприоритетное событие | Проверить версию сервера и признаки успешной эксплуатации |
| Плановая большая резервная копия | Может быть нормой | Сопоставить расписание и владельца, уточнить базовую линию |
| Необычный исходящий поток к неизвестному узлу | Возможная утечка/управление | Проверить процесс, DNS и endpoint-телеметрию |

Пример проверки службы IDS на машине, где пакет Suricata уже установлен и настроен на зеркальный интерфейс:
```bash
sudo suricata -T -c /etc/suricata/suricata.yaml
sudo systemctl status suricata --no-pager
sudo tail -n 50 /var/log/suricata/fast.log
sudo journalctl -u suricata --since '-15 min' --no-pager
```
**Критерий решения:** для каждого сигнала указаны время, источник, цель, правило, контекст и действие. Пассивная IDS только сообщает; блокировку выполняют отдельно по утверждённой процедуре. Содержимое зашифрованного SSH/TLS обычная NIDS не видит, поэтому неудачные SSH-входы требуют журналов сервера.

## Задание 35

Настройте защищённую беспроводную сеть и сравните результат подключения при использовании корректного и неверного ключа.

### Решение

#### Шаг 1. Добавьте оборудование

Откройте **Cisco Packet Tracer → File → New**. Добавьте:

- **1 Wi-Fi-маршрутизатор WRT300N:** внизу **Network Devices → Wireless Devices → WRT300N**.
- **1 ноутбук Laptop-PT:** **End Devices → Laptop-PT**, имя Laptop.
- **1 компьютер PC-PT:** **End Devices → PC-PT**, имя PC.

SSID — название Wi-Fi-сети, которое человек видит при подключении. В этой работе это **ExamWiFi**. WPA2 — защита Wi-Fi паролем. Отдельный свитч здесь не нужен: в WRT300N уже есть разъёмы для проводных компьютеров.

#### Шаг 2. Подключите компьютер кабелем

1. Нажмите **Connections** (молния) → **Copper Straight-Through** (прямой кабель).
2. Нажмите **PC → FastEthernet0**, затем **WRT300N → Ethernet 1**.
3. Не выбирайте разъём **Internet**. Ноутбук кабелем не подключайте — он будет работать по Wi-Fi.

#### Шаг 3. Проверьте Wi-Fi у ноутбука

Нажмите **Laptop → Desktop → PC Wireless**. Если программа открывается и видит беспроводной адаптер, переходите к следующему шагу. Если появляется требование установить WPC300N: откройте **Physical**, выключите ноутбук кнопкой питания на рисунке, выньте установленный сетевой модуль из слота и перетащите туда **WPC300N** из списка слева. Снова включите питание. Модуль — небольшая плата, которая даёт ноутбуку Wi-Fi.

#### Шаг 4. Настройте маршрутизатор

1. Нажмите **WRT300N → GUI → Setup → Basic Setup**.
2. В разделе **Network Setup / Router IP** задайте **Local IP Address: 192.168.50.1**, **Subnet Mask: 255.255.255.0**.
3. В разделе **DHCP Server** выберите **Enable**. Это автоматическая выдача адресов клиентам. **Start IP Address: 192.168.50.100** (если поле содержит только последний октет — введите 100), **Maximum Number of Users: 50**.
4. Нажмите **Save Settings** внизу страницы.
5. Откройте **Wireless → Basic Wireless Settings**. В **Network Name (SSID)** введите `ExamWiFi`, сохраните **Save Settings**.
6. Откройте **Wireless → Wireless Security**. **Security Mode: WPA2 Personal**, **Encryption: AES**, **Passphrase: Exam-WiFi-2026-Study!**. Нажмите **Save Settings**. Это учебный пароль для этой схемы.

#### Шаг 5. Настройте проводной компьютер

Нажмите **PC → Desktop → IP Configuration → Static**. Заполните:

| Поле | Значение |
|---|---|
| IP Address | 192.168.50.10 |
| Subnet Mask | 255.255.255.0 |
| Default Gateway | 192.168.50.1 |

Закройте окно. Адрес сохраняется автоматически.

#### Шаг 6. Подключите ноутбук к Wi-Fi

1. Нажмите **Laptop → Desktop → PC Wireless → Connect**.
2. При необходимости нажмите **Refresh**, выберите **ExamWiFi**, нажмите **Connect**.
3. Введите пароль `Exam-WiFi-2026-Study!`, подтвердите подключение.
4. Закройте PC Wireless. Откройте **Desktop → IP Configuration → DHCP**, дождитесь адреса от 192.168.50.100 до 192.168.50.149.

#### Шаг 7. Проверьте связь

Нажмите **Laptop → Desktop → Command Prompt**. Вводите по одной команде и нажимайте Enter:

```bat
ipconfig
ping 192.168.50.1
ping 192.168.50.10
```

`ipconfig` показывает полученный адрес. `Reply from ...` при ping означает, что ноутбук связался с маршрутизатором и проводным компьютером. Если написано `Request timed out`, проверьте выбранную Wi-Fi-сеть, пароль и адрес PC. Сохраните схему: **File → Save As**. Внешний Интернет для этой работы не требуется.

#### Шаг 8. Сравните правильный и неправильный пароль

1. С правильным паролем убедитесь, что `ping 192.168.50.1` возвращает ответы.
2. Откройте **Laptop → Desktop → PC Wireless**. В разделе **Profiles** удалите сохранённый профиль ExamWiFi (выделите его → **Delete**) или отключите текущее соединение и создайте новый профиль.
3. Снова выберите ExamWiFi через **Connect**, но введите `Wrong-Exam-Key!`.
4. Соединение не должно установиться, ping маршрутизатора не должен получать ответы. Если ноутбук всё ещё подключён, сначала убедитесь, что старое соединение действительно разорвано: одного изменения текста пароля недостаточно.
5. Подключитесь с правильным паролем и ещё раз выполните ping. Запишите в ответе: «С верным паролем связь есть, с неверным — аутентификация не проходит», то есть сеть не принимает пароль.

## Задание 36

Составьте план резервного копирования сетевых настроек и данных и опишите порядок восстановления после сбоя.

### Решение

#### Часть 1. Скопируйте настройки маршрутизатора в Packet Tracer

Добавьте **1 маршрутизатор 2911 — R1**, **1 свитч 2960 — SW1**, **1 Server-PT — Backup**. Внизу выберите **Connections → Copper Straight-Through**: сначала соедините **R1 GigabitEthernet0/0** с **SW1 GigabitEthernet0/1**, затем **Backup FastEthernet0** с **SW1 FastEthernet0/1**.

Нажмите **Backup → Desktop → IP Configuration → Static**: IP `192.168.10.50`, Subnet Mask `255.255.255.0`, Default Gateway `192.168.10.1`. Затем **Services → TFTP → On** — включите приём файлов настроек.

#### Как вводить команды на свитче или маршрутизаторе

1. Нажмите **устройство, названное перед блоком команд**.
2. Откройте вкладку **CLI** — это окно для ввода команд.
3. Нажмите Enter. Если появится `Would you like to enter the initial configuration dialog? [yes/no]:`, напишите `no` и нажмите Enter. При сообщении `Press RETURN to get started` ещё раз нажмите Enter. Если ещё идёт загрузка, дождитесь приглашения ввода.
4. Вводите строки блока сверху вниз, нажимая **Enter после каждой**. Копируйте только команды внутри блока. Надписи вида `Router>` или `Router#` устройство выводит само.
5. Команда `enable` открывает расширенный режим, `configure terminal` — настройку, `interface` выбирает разъём, `ip address` задаёт ему адрес, `no shutdown` включает разъём, `exit` возвращает на уровень выше, `end` завершает настройку.
6. Последняя команда `copy running-config startup-config` сохраняет настройки. На вопрос `Destination filename [startup-config]?` нажмите **Enter**, дождитесь `[OK]`.

Если ниже снова открываете то же устройство для исправления, начните с указанного блока. Команды проверки `show ...` вводятся после выхода из настройки командой `end`, когда строка заканчивается `#`; если видите `>`, сначала введите `enable`.

Нажмите **R1 → CLI**, выполните:

```cisco
enable
configure terminal
interface g0/0
 ip address 192.168.10.1 255.255.255.0
 no shutdown
end
copy running-config startup-config
```

Нажмите Enter на вопрос об имени файла. Теперь выполняйте план копирования ниже. После `copy running-config tftp:` на вопрос **Address or name of remote host** введите `192.168.10.50`, на вопрос **Destination filename** — `R1-before-change.cfg`. На сервере **Services → TFTP** проверьте, что файл появился.

#### Часть 2. Копирование обычных файлов Linux

Эта часть выполняется на отдельном Ubuntu-компьютере с папкой `/srv/data` и подключённым носителем копий `/mnt/backup`. Она не выполняется на Server-PT. «Резервная копия» — отдельный экземпляр данных, который можно вернуть после потери основного.

#### Где вводить команды Linux

Все команды этого раздела вводятся **внутри нужного компьютера Ubuntu**, не в PowerShell Windows и не в окне Cisco Packet Tracer. Откройте окно этой виртуальной машины, войдите в Ubuntu. В Ubuntu с рабочим столом нажмите **Ctrl+Alt+T** — откроется Терминал; в Ubuntu Server командная строка появляется после входа.

Вводите одну строку за другой и нажимайте Enter. `sudo` означает выполнить действие с правами администратора: введите пароль Ubuntu; символы пароля при вводе не отображаются — это нормально. `apt install` устанавливает программу и требует доступа к репозиторию. Установите программы до отключения Интернета в учебной сети.

Если сказано «создайте файл», откройте его командой `sudo nano /полный/путь/к/файлу`, вставьте приведённый текст, нажмите **Ctrl+O → Enter** для сохранения, затем **Ctrl+X** для выхода. Блоки `ini` и `yaml` — **содержимое файлов**, их не вводят построчно как команды. Строки в блоке `bash` — команды терминала. Для обычного файла в домашней папке достаточно `nano имя-файла`.

**Схема:** `маршрутизаторы/серверы → закрытый сервер копий → отдельная офлайн/неизменяемая копия`. Учебный пример: Cisco R1 и Ubuntu-файловый сервер, хранилище копий доступно только администраторам.

**План:** конфигурации устройств копировать после каждого согласованного изменения и ежедневно; данные — ежедневно, критичную БД дополнительно по журналам транзакций. Для примера RPO=24 часа, RTO=4 часа. Хранить 7 ежедневных, 4 недельных и 6 месячных копий, шифровать и проверять восстановлением ежемесячно. Владельцем восстановления назначить администратора.

На Cisco сохраняйте рабочую конфигурацию:
```cisco
copy running-config startup-config
show startup-config
copy running-config tftp:
```
В учебной изолированной LAN укажите TFTP Server-PT 192.168.10.50 с Services → TFTP On и имя `R1-before-change.cfg`. TFTP не шифрует конфигурацию: в рабочей сети используйте поддерживаемый SCP/SFTP или защищённый сборщик.

На Ubuntu пример резервирования обычного каталога, где `/mnt/backup` — отдельный смонтированный носитель:
```bash
findmnt /mnt/backup
sudo tar --acls --xattrs -czf /mnt/backup/data-2026-10-11.tar.gz /srv/data
sha256sum /mnt/backup/data-2026-10-11.tar.gz
tar -tzf /mnt/backup/data-2026-10-11.tar.gz | head
```
Живую БД архивируют её средствами или согласованным snapshot, а не простым tar открытых файлов.

**Восстановление:** локализовать причину сбоя → выбрать проверенную копию → поднять чистое совместимое оборудование → восстановить конфигурации, данные и права → проверить сеть и приложения → открыть доступ пользователям. На Cisco `copy tftp: running-config` объединяет конфигурации, поэтому для точного восстановления используйте чистое устройство; затем сохраните startup-config. Архив данных сначала извлеките в отдельный каталог и сравните: `sudo mkdir -p /tmp/restore-check`, `sudo tar --acls --xattrs -xzf /mnt/backup/data-2026-10-11.tar.gz -C /tmp/restore-check`. Проверка включает хеши, чтение файлов и реальный запуск службы.
