# Сетевое администрирование · практика 37–40

## Задание 37

Спроектируйте схему защищённого подключения корпоративной сети к облачному сервису и укажите основные меры защиты.

### Решение

#### Что требуется в этом задании

Здесь нужно **спроектировать подключение**, то есть нарисовать схему и описать настройки. Покупать облачный сервис и создавать платные ресурсы для письменного ответа не требуется. Конкретный облачный провайдер в условии не указан, поэтому универсальных названий его кнопок нет.

#### Оборудование и простая схема подключения

1. Компьютеры сотрудников подключите к офисному свитчу.
2. Свитч подключите к офисному маршрутизатору, который поддерживает VPN.
3. Второй разъём маршрутизатора подключается к оборудованию интернет-провайдера.
4. В облаке предусмотрите VPN-шлюз, сервер приложения и отдельный сервер базы данных.
5. Между офисным маршрутизатором и облачным VPN-шлюзом создаётся защищённое соединение через Интернет. Оно заменяет прямой кабель между офисом и облаком.

VPN — защищённый канал. VPC — отдельная сеть внутри облака. CIDR — диапазон адресов, например 10.20.0.0/16. Firewall / security group — правила, какие подключения разрешены. IAM — права учётных записей. MFA — подтверждение входа вторым фактором.

#### Готовый проект и порядок настройки

**Проектная схема:**
```text
Офис 10.10.0.0/16 → корпоративный firewall/VPN gateway
                       ║ зашифрованный site-to-site VPN
Интернет               ║
                       ║
Облачный VPN gateway → VPC 10.20.0.0/16
                         ├─ приложение 10.20.10.10
                         └─ БД 10.20.20.10 (без публичного IP)
```
**Устройства:** офисный VPN-шлюз с поддержкой IPsec/IKEv2, облачный VPN gateway, виртуальные маршрутизаторы, firewall/security groups, DNS и централизованные журналы. Конкретный провайдер не указан, поэтому это проект и последовательность настройки, а не вымышленная команда облачного CLI.

1. Выделить непересекающиеся CIDR, создать VPC и подсети приложения/БД; запретить публичный доступ к БД.
2. Создать site-to-site VPN, настроить на обеих сторонах совместимые алгоритмы IKEv2/IPsec, идентификацию и ключи; внешний адрес и параметры взять из конфигурации провайдера.
3. Добавить маршруты офиса к 10.20.0.0/16 через VPN, облака к 10.10.0.0/16 через облачный шлюз; не подменять этот трафик PAT, если VPN требует исходные подсети.
4. Разрешить офису HTTPS к 10.20.10.10, а приложению — только нужный порт БД; администрирование ограничить отдельной сетью и MFA/IAM. Настроить частный DNS и журналы туннеля.
5. Предусмотреть второй туннель/шлюз и проверить отказ основного.

**Проверка с офисного Linux:** `ip route get 10.20.10.10`, `curl --cacert corp-ca.crt https://app.corp.example`, `nc -vz 10.20.20.10 5432`. Имя app.corp.example в корпоративном DNS должно указывать на .10, сертификат — соответствовать имени. HTTPS должен работать, прямой доступ офиса к БД — блокироваться. В журналах VPN — активная SA и рост счётчиков; трассировка сама по себе не доказывает шифрование.

Команды проверки выполняются **на офисном Linux-компьютере**, где уже настроены адрес, маршрут, имя приложения и выдан файл сертификата `corp-ca.crt`: откройте терминал через Ctrl+Alt+T. При письменном проектировании опишите ожидаемые результаты, не представляйте их как реально выполненные проверки.

## Задание 38

Для сети с рабочими станциями предложите и настройте меры защиты конечных устройств от сетевых угроз.

### Решение

#### Шаг 1. Подготовьте оборудование

Нужны **4 Ubuntu-компьютера**: **Work** — защищаемая рабочая станция, **Other** — второй пользовательский компьютер, **Router** — маршрутизатор с двумя сетевыми картами, **Admin** — компьютер администратора. Схема: **Work и Other к первому свитчу; свитч к Router; другой разъём Router ко второму свитчу; Admin ко второму свитчу**.

На Work заранее, при доступном Интернете, установите обновления и программы: `sudo apt update`, `sudo apt upgrade`, `sudo apt install unattended-upgrades ufw openssh-server`. На Admin и Other установите `sudo apt install openssh-client`. Затем соедините машины:

#### Как соединить виртуальные компьютеры

Виртуальная машина — отдельный компьютер внутри программы VirtualBox. Здесь нужны машины с **уже установленной ОС**; установка Windows/Ubuntu не является частью сетевого задания. Реальные кабели на экране не рисуются: компьютеры с одинаковым именем внутренней сети соединяются так, будто подключены к одному свитчу.

1. Полностью выключите учебные виртуальные машины.
2. В главном окне VirtualBox выберите машину → **Settings / Настроить → Network / Сеть**.
3. Откройте **Adapter 1 / Адаптер 1** (либо другой номер из таблицы), поставьте **Enable Network Adapter / Включить сетевой адаптер**.
4. В **Attached to / Тип подключения** выберите **Internal Network / Внутренняя сеть**. В **Name / Имя** впишите имя из таблицы. В дополнительных настройках оставьте **Cable Connected / Кабель подключён** включённым.
5. Повторите для каждой строки, нажмите **OK**, затем запустите машины.

| Компьютер | Адаптер | Имя внутренней сети |
|---|---|---|
| Work | 1 | exam-work |
| Other | 1 | exam-work |
| Router | 1 | exam-work |
| Router | 2 | exam-admin |
| Admin | 1 | exam-admin |

Ниже адреса настраиваются **внутри ОС каждой машины**. Название разъёма Linux узнайте командой `ip -br link`: обычно первый — enp0s3, второй — enp0s8; при отличии заменяйте имя в командах. [Справка Oracle по внутренним сетям](https://docs.oracle.com/en/virtualization/virtualbox/7.1/user/networkingdetails.html).

#### Где вводить команды Linux

Все команды этого раздела вводятся **внутри нужного компьютера Ubuntu**, не в PowerShell Windows и не в окне Cisco Packet Tracer. Откройте окно этой виртуальной машины, войдите в Ubuntu. В Ubuntu с рабочим столом нажмите **Ctrl+Alt+T** — откроется Терминал; в Ubuntu Server командная строка появляется после входа.

Вводите одну строку за другой и нажимайте Enter. `sudo` означает выполнить действие с правами администратора: введите пароль Ubuntu; символы пароля при вводе не отображаются — это нормально. `apt install` устанавливает программу и требует доступа к репозиторию. Установите программы до отключения Интернета в учебной сети.

Если сказано «создайте файл», откройте его командой `sudo nano /полный/путь/к/файлу`, вставьте приведённый текст, нажмите **Ctrl+O → Enter** для сохранения, затем **Ctrl+X** для выхода. Блоки `ini` и `yaml` — **содержимое файлов**, их не вводят построчно как команды. Строки в блоке `bash` — команды терминала. Для обычного файла в домашней папке достаточно `nano имя-файла`.

#### Шаг 2. Укажите адреса

**На Router (Ubuntu)** откройте терминал. Здесь первая карта соединена с компьютерами, вторая — с другой сетью:

```bash
sudo ip link set enp0s3 up
sudo ip link set enp0s8 up
sudo ip addr add 192.168.10.1/24 dev enp0s3
sudo ip addr add 192.168.99.1/24 dev enp0s8
sudo sysctl -w net.ipv4.ip_forward=1
```

Последняя команда разрешает Ubuntu передавать данные между двумя картами — теперь она работает как маршрутизатор. Это чистый учебный маршрутизатор без включённого UFW и других ограничивающих правил. Настройки `ip addr` временные, до перезагрузки. Если адрес уже существует, второй раз его добавлять не нужно.

**На Work** откройте терминал и выполните:

```bash
sudo ip link set enp0s3 up
sudo ip addr add 192.168.10.10/24 dev enp0s3
sudo ip route replace default via 192.168.10.1
```

**На Other** откройте терминал и выполните:

```bash
sudo ip link set enp0s3 up
sudo ip addr add 192.168.10.11/24 dev enp0s3
sudo ip route replace default via 192.168.10.1
```

**На Admin** откройте терминал и выполните:

```bash
sudo ip link set enp0s3 up
sudo ip addr add 192.168.99.10/24 dev enp0s3
sudo ip route replace default via 192.168.99.1
```

На Work выполните `sudo systemctl start ssh`; команда `whoami` покажет имя учётной записи. Здесь две отдельные внутренние сети выполняют роль двух разделённых групп устройств. VLAN — способ сделать такое разделение на управляемом свитче; в данном варианте VirtualBox отдельная команда VLAN не нужна.

#### Шаг 3. Защитите рабочую станцию

Следующие команды выполняйте **на Work**. Первые команды обновления требуют Интернета: если вы уже выполнили их перед изоляцией, повторять их сейчас не нужно. Остальная настройка UFW работает без Интернета. SSH — удалённая командная строка; разрешаем её только с Admin.

**Среда:** Ubuntu 24.04, Work 192.168.10.10, шлюз 192.168.10.1; Admin 192.168.99.10 расположен в отдельной сети управления. На учебной станции через локальную консоль:

```bash
sudo apt update
sudo apt upgrade
sudo apt install unattended-upgrades ufw
sudo dpkg-reconfigure -plow unattended-upgrades
sudo ufw default deny incoming
sudo ufw default allow outgoing
sudo ufw allow from 192.168.99.10 to any port 22 proto tcp
sudo ufw enable
sudo ufw status verbose
ss -tulpen
```
Правило SSH нужно только если OpenSSH установлен и удалённое администрирование требуется; иначе не открывайте его. Проверьте предыдущие разрешения UFW, чтобы широкое старое правило не обходило ограничение. Отключите ненужные службы по найденным именам через `sudo systemctl disable --now ИМЯ_СЛУЖБЫ`, не отключая сетевое управление наугад.

Дополнительно: отдельная обычная учётная запись без повседневной работы root, SSH-ключи, MFA у корпоративных сервисов, шифрование диска при установке, резервные копии и утверждённый EDR/антивирус с централизованным контролем. Перед запретом пароля SSH проверьте вход по ключу отдельной сессией.

**Проверка:** обновления устанавливаются, лишние порты не слушаются, SSH с разрешённого администратора работает, с пользовательского PC — блокируется. Запишите `systemctl status unattended-upgrades`, состояние защиты и дату пробного восстановления. Сегментация сети дополняет защиту хоста, а не заменяет её.

#### Шаг 4. Проверьте ограничения

На **Admin** откройте терминал и выполните `ssh ИМЯ_ПОЛЬЗОВАТЕЛЯ@192.168.10.10`, подставив результат `whoami` с Work. Вход должен работать. На **Other** та же команда должна блокироваться. На Work команда `sudo ufw status verbose` показывает правило для 192.168.99.10. EDR — средство наблюдения и реагирования на подозрительные действия компьютера; его установка зависит от выбранного организацией продукта и не заменяет выполненные настройки.

## Задание 39

Спроектируйте корпоративную сеть с IPv4-адресацией, VLAN, межвлановой маршрутизацией и DHCP; проверьте связность всех сегментов.

### Решение

#### Шаг 1. Добавьте оборудование

Откройте Cisco Packet Tracer → **File → New** (Файл → Новый). Внизу слева выбирайте категорию, затем модель и щёлкайте по свободному месту рабочего поля.

- **Компьютеры: 2 шт.** Нажмите **End Devices (Конечные устройства)**, выберите **PC-PT**. Имена в инструкции: **PC10, PC20**.
- **Свитчи: 1 шт.** Нажмите **Network Devices → Switches (Сетевые устройства → Коммутаторы)**, выберите **2960**. Имена в инструкции: **SW1**.
- **Маршрутизаторы: 1 шт.** Нажмите **Network Devices → Routers (Маршрутизаторы)**, выберите **2911**. Имена в инструкции: **R1**.
- **Серверы: 1 шт.** Нажмите **End Devices (Конечные устройства)**, выберите **Server-PT**. Имена в инструкции: **Server**.

Чтобы задать имя, щёлкните по устройству → **Config → Display Name**, введите нужное имя и закройте окно. Название **свитч** и **коммутатор** означает одно и то же устройство: оно соединяет компьютеры. Маршрутизатор соединяет разные сети.

#### Шаг 2. Соедините устройства кабелями

Внизу слева нажмите **Connections** (значок молнии). Для каждой строки ниже заново выберите указанный кабель, затем щёлкните первое устройство и его разъём, после этого — второе устройство и его разъём.

1. Выберите **Copper Straight-Through (прямой медный кабель)**. Нажмите **PC10 → FastEthernet0**, затем **SW1 → FastEthernet0/1**.
2. Выберите **Copper Straight-Through (прямой медный кабель)**. Нажмите **PC20 → FastEthernet0**, затем **SW1 → FastEthernet0/3**.
3. Выберите **Copper Straight-Through (прямой медный кабель)**. Нажмите **SW1 → GigabitEthernet0/1**, затем **R1 → GigabitEthernet0/0**.
4. Выберите **Copper Straight-Through (прямой медный кабель)**. Нажмите **Server → FastEthernet0**, затем **SW1 → FastEthernet0/4**.

Разъём также называется **портом**. В командах `g0/0` — короткая запись GigabitEthernet0/0, `fa0/1` — FastEthernet0/1. У свитча индикатор может сначала быть оранжевым. Разъёмы маршрутизатора станут зелёными после команды `no shutdown` ниже — до настройки красный индикатор здесь допустим.

#### Что означают слова в этом задании

VLAN — отдельная группа устройств на одном свитче. Компьютеры разных групп без маршрутизатора не обмениваются данными. `access` назначает разъём одной группе; `trunk` разрешает передавать несколько групп по одному кабелю.

DHCP автоматически выдаёт компьютеру IP-адрес и другие настройки. «Пул» — набор адресов, которые разрешено выдавать. «Аренда» — выданный конкретному компьютеру адрес на определённое время.

#### Шаг 3. Укажите адреса устройств

Для **каждого** компьютера или сервера из таблицы:

1. Щёлкните по его значку на схеме.
2. Откройте вкладку **Desktop** (Рабочий стол).
3. Нажмите **IP Configuration** (Настройка IP) и выберите **Static** (Вручную).
4. Перепишите значения **из строки именно этого устройства**: «IPv4» → **IPv4 Address / IP Address**, «Маска» → **Subnet Mask**, «Шлюз» → **Default Gateway**.
5. Если у шлюза написано «не нужен», оставьте поле пустым или 0.0.0.0. Остальные поля без указания не меняйте. Закройте окно — значения сохраняются автоматически.

IP-адрес — номер устройства в сети. Маска показывает границы его сети. Шлюз — адрес маршрутизатора, через который компьютер обращается в другие сети. Запись `/24` в пояснениях означает маску 255.255.255.0, `/30` — 255.255.255.252, `/29` — 255.255.255.248. В поля таблицы вводите обычные адреса и маски, без `/24`.


| Узел | IPv4 | Маска | Шлюз |
|---|---|---|---|
| PC10 | 192.168.10.10 | 255.255.255.0 | 192.168.10.1 |
| PC20 | 192.168.20.10 | 255.255.255.0 | 192.168.20.1 |

#### Что делают основные команды

`interface g0/0.10` создаёт отдельную настройку для группы 10 на том же физическом разъёме. `encapsulation dot1Q 10` связывает её с VLAN 10. Второй кабель для этой группы не нужен.

`ip dhcp pool` создаёт набор выдаваемых адресов. `default-router` сообщает компьютерам адрес шлюза, `dns-server` — адрес службы имён. `excluded-address` исключает адреса, которые нельзя выдавать автоматически.

#### Как вводить команды на свитче или маршрутизаторе

1. Нажмите **устройство, названное перед блоком команд**.
2. Откройте вкладку **CLI** — это окно для ввода команд.
3. Нажмите Enter. Если появится `Would you like to enter the initial configuration dialog? [yes/no]:`, напишите `no` и нажмите Enter. При сообщении `Press RETURN to get started` ещё раз нажмите Enter. Если ещё идёт загрузка, дождитесь приглашения ввода.
4. Вводите строки блока сверху вниз, нажимая **Enter после каждой**. Копируйте только команды внутри блока. Надписи вида `Router>` или `Router#` устройство выводит само.
5. Команда `enable` открывает расширенный режим, `configure terminal` — настройку, `interface` выбирает разъём, `ip address` задаёт ему адрес, `no shutdown` включает разъём, `exit` возвращает на уровень выше, `end` завершает настройку.
6. Последняя команда `copy running-config startup-config` сохраняет настройки. На вопрос `Destination filename [startup-config]?` нажмите **Enter**, дождитесь `[OK]`.

Если ниже снова открываете то же устройство для исправления, начните с указанного блока. Команды проверки `show ...` вводятся после выхода из настройки командой `end`, когда строка заканчивается `#`; если видите `>`, сначала введите `enable`.

#### Настройте свитч SW1

Нажмите **SW1 → CLI**. Выполните следующие команды **на этом устройстве**, по одной строке:


```cisco
enable
configure terminal
vlan 10
 name USERS
 exit
vlan 20
 name SERVERS
 exit
interface range fa0/1 - 2
 switchport mode access
 switchport access vlan 10
 spanning-tree portfast
 exit
interface range fa0/3 - 4
 switchport mode access
 switchport access vlan 20
 spanning-tree portfast
 exit
interface g0/1
 switchport mode trunk
 switchport trunk allowed vlan 10,20
 no shutdown
 exit
end
copy running-config startup-config
```

#### Настройте маршрутизатор R1

Нажмите **R1 → CLI**. Выполните следующие команды **на этом устройстве**, по одной строке:


```cisco
enable
configure terminal
interface g0/0
 no ip address
 no shutdown
 exit
interface g0/0.10
 encapsulation dot1Q 10
 ip address 192.168.10.1 255.255.255.0
 exit
interface g0/0.20
 encapsulation dot1Q 20
 ip address 192.168.20.1 255.255.255.0
 exit
end
copy running-config startup-config
```

**Расширение до корпоративной сети:** После выполнения последних команд R1 ниже нажмите **PC10 → Desktop → IP Configuration → DHCP**, затем повторите на **PC20**. DHCP сам заменит введённые вручную адреса. Сервер уже подключён к SW1. Нажмите **Server → Desktop → IP Configuration → Static**: IP Address `192.168.20.53`, Subnet Mask `255.255.255.0`, Default Gateway `192.168.20.1`. Затем **Services → DNS → On**: Name `intranet.lab.test`, Type `A Record`, Address `192.168.20.53` → **Add**. Откройте **Services → HTTP → On**.

#### Настройте маршрутизатор R1

Нажмите **R1 → CLI**. Выполните следующие команды **на этом устройстве**, по одной строке:


```cisco
enable
configure terminal
ip dhcp excluded-address 192.168.10.1 192.168.10.99
ip dhcp pool LAN10
 network 192.168.10.0 255.255.255.0
 default-router 192.168.10.1
 dns-server 192.168.20.53
 exit
ip dhcp excluded-address 192.168.20.1 192.168.20.99
ip dhcp pool LAN20
 network 192.168.20.0 255.255.255.0
 default-router 192.168.20.1
 dns-server 192.168.20.53

end
copy running-config startup-config
```
#### Где выполнять проверку

- **На компьютере:** нажмите его значок → **Desktop → Command Prompt** (Командная строка). Введите приведённую ниже команду `ping ...` и нажмите Enter. `Reply from ...` означает, что ответ получен; `Request timed out` — ответа нет. Первый запрос иногда не успевает пройти, поэтому повторите проверку.
- **На маршрутизаторе или свитче:** нажмите устройство → **CLI**. Для команд `show ...` используйте режим `#`, как объяснено выше.
- **Для страницы сайта:** нажмите компьютер → **Desktop → Web Browser**, введите адрес из задания и нажмите **Go**. Адрес сайта не вводят в CLI маршрутизатора.

**Проверка:** PC10 получает 192.168.10.100–254, PC20 — 192.168.20.100–254, DNS обоих .20.53. На R1 `show ip dhcp binding`, `show ip route`; на SW1 `show vlan brief`, `show interfaces trunk`. С каждого клиента ping своего шлюза, другого клиента и 192.168.20.53, затем `nslookup intranet.lab.test` и HTTP по имени. Оба сегмента должны быть связны; ACL намеренно добавляются в отдельном задании, чтобы не противоречить проверке всех сегментов.

Справка: [Cisco — межвлановая маршрутизация 802.1Q](https://www.cisco.com/c/en/us/td/docs/ios-xml/ios/lanswitch/configuration/xe-16-9/lanswitch-xe-16-9-book/lnsw-conf-vlan-ieee.pdf).

## Задание 40

Выполните итоговую настройку защищённой корпоративной сети, включив адресацию, маршрутизацию, ACL, VPN и мониторинг.

### Решение

#### Шаг 1. Подготовьте оборудование

Нужны **4 виртуальных компьютера Ubuntu 24.04** с уже установленной ОС:

- **PC-A** — обычный компьютер сотрудника, 1 сетевая карта.
- **GW-A** — маршрутизатор первого офиса, 2 сетевые карты.
- **GW-B** — маршрутизатор второго офиса, 2 сетевые карты.
- **Server-B** — сервер сайта второго офиса, 1 сетевая карта.

Здесь GW означает шлюз/маршрутизатор. Его роль выполняет Ubuntu, поэтому отдельные устройства Cisco не добавляются. До изоляции сетей установите нужные программы: на GW-A и GW-B — `sudo apt install wireguard iptables iptables-persistent`, на Server-B — `sudo apt install nginx python3`, на PC-A — `sudo apt install curl`. Команды вводятся внутри соответствующей Ubuntu.

#### Шаг 2. Соедините компьютеры

Простыми словами: **PC-A подключён к GW-A; GW-A подключён к GW-B; GW-B подключён к Server-B**. Для этого используются три отдельных виртуальных свитча. В VirtualBox свитч создаётся общим именем внутренней сети:

#### Как соединить виртуальные компьютеры

Виртуальная машина — отдельный компьютер внутри программы VirtualBox. Здесь нужны машины с **уже установленной ОС**; установка Windows/Ubuntu не является частью сетевого задания. Реальные кабели на экране не рисуются: компьютеры с одинаковым именем внутренней сети соединяются так, будто подключены к одному свитчу.

1. Полностью выключите учебные виртуальные машины.
2. В главном окне VirtualBox выберите машину → **Settings / Настроить → Network / Сеть**.
3. Откройте **Adapter 1 / Адаптер 1** (либо другой номер из таблицы), поставьте **Enable Network Adapter / Включить сетевой адаптер**.
4. В **Attached to / Тип подключения** выберите **Internal Network / Внутренняя сеть**. В **Name / Имя** впишите имя из таблицы. В дополнительных настройках оставьте **Cable Connected / Кабель подключён** включённым.
5. Повторите для каждой строки, нажмите **OK**, затем запустите машины.

| Компьютер | Адаптер | Имя внутренней сети |
|---|---|---|
| PC-A | 1 | exam-office-a |
| GW-A | 2 | exam-office-a |
| GW-A | 1 | exam-between |
| GW-B | 1 | exam-between |
| GW-B | 2 | exam-office-b |
| Server-B | 1 | exam-office-b |

Ниже адреса настраиваются **внутри ОС каждой машины**. Название разъёма Linux узнайте командой `ip -br link`: обычно первый — enp0s3, второй — enp0s8; при отличии заменяйте имя в командах. [Справка Oracle по внутренним сетям](https://docs.oracle.com/en/virtualization/virtualbox/7.1/user/networkingdetails.html).

#### Где вводить команды Linux

Все команды этого раздела вводятся **внутри нужного компьютера Ubuntu**, не в PowerShell Windows и не в окне Cisco Packet Tracer. Откройте окно этой виртуальной машины, войдите в Ubuntu. В Ubuntu с рабочим столом нажмите **Ctrl+Alt+T** — откроется Терминал; в Ubuntu Server командная строка появляется после входа.

Вводите одну строку за другой и нажимайте Enter. `sudo` означает выполнить действие с правами администратора: введите пароль Ubuntu; символы пароля при вводе не отображаются — это нормально. `apt install` устанавливает программу и требует доступа к репозиторию. Установите программы до отключения Интернета в учебной сети.

Если сказано «создайте файл», откройте его командой `sudo nano /полный/путь/к/файлу`, вставьте приведённый текст, нажмите **Ctrl+O → Enter** для сохранения, затем **Ctrl+X** для выхода. Блоки `ini` и `yaml` — **содержимое файлов**, их не вводят построчно как команды. Строки в блоке `bash` — команды терминала. Для обычного файла в домашней папке достаточно `nano имя-файла`.

#### Шаг 3. Выполните настройку по порядку

На каждом шаге сначала переключайтесь **в окно компьютера с указанным именем**. `enp0s3` обычно соответствует первому адаптеру VirtualBox, `enp0s8` — второму; проверьте через `ip -br link`. WireGuard создаст `wg0` — виртуальное защищённое соединение между офисами. ACL / firewall — правила разрешения и запрета данных; FORWARD относится к данным, проходящим через маршрутизатор от одного компьютера к другому.

**1. Адресация.** Проверьте имена `ip -br link`. Команды ниже выполняются на чистых лабораторных интерфейсах; адреса не добавляют повторно, если они уже назначены.

GW-A:
```bash
sudo ip link set enp0s3 up
sudo ip link set enp0s8 up
sudo ip addr add 192.168.56.10/24 dev enp0s3
sudo ip addr add 10.10.10.1/24 dev enp0s8
sudo sysctl -w net.ipv4.ip_forward=1
```
GW-B:
```bash
sudo ip link set enp0s3 up
sudo ip link set enp0s8 up
sudo ip addr add 192.168.56.20/24 dev enp0s3
sudo ip addr add 10.20.20.1/24 dev enp0s8
sudo sysctl -w net.ipv4.ip_forward=1
```
PC-A:
```bash
sudo ip link set enp0s3 up
sudo ip addr add 10.10.10.10/24 dev enp0s3
sudo ip route replace default via 10.10.10.1
```
Server-B:
```bash
sudo ip link set enp0s3 up
sudo ip addr add 10.20.20.10/24 dev enp0s3
sudo ip route replace default via 10.20.20.1
sudo systemctl enable --now nginx
```
**2. VPN и маршруты.** На обоих шлюзах сгенерируйте ключи:
```bash
sudo install -d -m 700 /etc/wireguard
sudo sh -c 'umask 077; wg genkey > /etc/wireguard/private.key; wg pubkey < /etc/wireguard/private.key > /etc/wireguard/public.key'
sudo cat /etc/wireguard/public.key
```
Вставьте свои ключи вместо меток, создайте `/etc/wireguard/wg0.conf` на GW-A:
```ini
[Interface]
Address = 10.8.0.1/30
ListenPort = 51820
PrivateKey = <PRIVATE_KEY_A>
[Peer]
PublicKey = <PUBLIC_KEY_B>
Endpoint = 192.168.56.20:51820
AllowedIPs = 10.8.0.2/32, 10.20.20.0/24
PersistentKeepalive = 25
```
На GW-B:
```ini
[Interface]
Address = 10.8.0.2/30
ListenPort = 51820
PrivateKey = <PRIVATE_KEY_B>
[Peer]
PublicKey = <PUBLIC_KEY_A>
Endpoint = 192.168.56.10:51820
AllowedIPs = 10.8.0.1/32, 10.10.10.0/24
PersistentKeepalive = 25
```
На обоих: `sudo chmod 600 /etc/wireguard/wg0.conf`, `sudo wg-quick up wg0`. wg-quick добавляет маршруты к удалённым LAN из AllowedIPs. NAT между LAN не нужен. Проверьте `ip route`, `sudo wg show`, затем ping между туннельными адресами.

**3. ACL/firewall.** Политика: из LAN-A в Server-B разрешены только HTTP и ICMP; ответный трафик разрешён, другие новые транзитные соединения запрещены. На обоих шлюзах сначала проверьте `sudo iptables -S`: следующие команды рассчитаны на чистый стенд без старых разрешающих правил. На GW-A:
```bash
sudo iptables -A INPUT -i lo -j ACCEPT
sudo iptables -A INPUT -m conntrack --ctstate ESTABLISHED,RELATED -j ACCEPT
sudo iptables -A INPUT -i enp0s3 -s 192.168.56.20 -p udp --dport 51820 -j ACCEPT
sudo iptables -A INPUT -i enp0s8 -s 10.10.10.0/24 -p icmp -j ACCEPT
sudo iptables -A INPUT -i wg0 -s 10.8.0.2 -p icmp -j ACCEPT
sudo iptables -A FORWARD -m conntrack --ctstate ESTABLISHED,RELATED -j ACCEPT
sudo iptables -A FORWARD -i enp0s8 -o wg0 -s 10.10.10.0/24 -d 10.20.20.10 -p tcp --dport 80 -j ACCEPT
sudo iptables -A FORWARD -i enp0s8 -o wg0 -s 10.10.10.0/24 -d 10.20.20.10 -p icmp -j ACCEPT
sudo iptables -P INPUT DROP
sudo iptables -P FORWARD DROP
sudo iptables -P OUTPUT ACCEPT
```
На GW-B:
```bash
sudo iptables -A INPUT -i lo -j ACCEPT
sudo iptables -A INPUT -m conntrack --ctstate ESTABLISHED,RELATED -j ACCEPT
sudo iptables -A INPUT -i enp0s3 -s 192.168.56.10 -p udp --dport 51820 -j ACCEPT
sudo iptables -A INPUT -i enp0s8 -s 10.20.20.0/24 -p icmp -j ACCEPT
sudo iptables -A INPUT -i wg0 -s 10.8.0.1 -p icmp -j ACCEPT
sudo iptables -A FORWARD -m conntrack --ctstate ESTABLISHED,RELATED -j ACCEPT
sudo iptables -A FORWARD -i wg0 -o enp0s8 -s 10.10.10.0/24 -d 10.20.20.10 -p tcp --dport 80 -j ACCEPT
sudo iptables -A FORWARD -i wg0 -o enp0s8 -s 10.10.10.0/24 -d 10.20.20.10 -p icmp -j ACCEPT
sudo iptables -P INPUT DROP
sudo iptables -P FORWARD DROP
sudo iptables -P OUTPUT ACCEPT
```
Правила для IPv4 не защищают IPv6: в этом IPv4-стенде отключите его **на обоих шлюзах** через консоль:
```bash
sudo sysctl -w net.ipv6.conf.all.disable_ipv6=1
sudo sysctl -w net.ipv6.conf.default.disable_ipv6=1
``` Администрирование оставлено через консоль.

**4. Проверка и мониторинг.** На PC-A: `ping -c 4 10.20.20.10` и `curl --max-time 5 http://10.20.20.10` должны работать. Для достоверного запрещённого теста запустите на Server-B `python3 -m http.server 8080 --bind 10.20.20.10`, затем на PC-A `curl --max-time 5 http://10.20.20.10:8080` должен завершиться тайм-аутом; локально на Server-B порт 8080 доступен. На шлюзах `sudo iptables -L -n -v`, `sudo wg show` и `ip -s link show wg0` показывают счётчики.

На PC-A мониторьте прикладную доступность:
```bash
for n in {1..12}; do
  date -Is
  curl --fail --silent --max-time 3 http://10.20.20.10/ >/dev/null && echo HTTP_UP || echo HTTP_DOWN
  sleep 5
done
```
В консоли GW-B временно `sudo wg-quick down wg0`: доступ должен пропасть; `sudo wg-quick up wg0` восстанавливает его. Это проверка VPN-зависимости, а не только локального порта.

**5. Сохранение.** После проверок закрепите адреса через Netplan, `net.ipv4.ip_forward=1` в `/etc/sysctl.d/99-exam.conf`, включите `sudo systemctl enable wg-quick@wg0`. Для firewall установите iptables-persistent и сохраните `sudo netfilter-persistent save`; не смешивайте этот способ с UFW. Перезагрузите учебные VM и повторите положительные/отрицательные тесты. Итоговый отчёт должен содержать адресный план, состояние handshake, разрешённый HTTP, заблокированный 8080 и реакцию мониторинга.
**Пример постоянной адресации GW-A.** В единственном активном файле Netplan, например `/etc/netplan/01-exam.yaml`, задайте (не оставляйте конфликтующий DHCP в других файлах):
```yaml
network:
  version: 2
  renderer: networkd
  ethernets:
    enp0s3:
      dhcp4: false
      dhcp6: false
      accept-ra: false
      addresses: [192.168.56.10/24]
    enp0s8:
      dhcp4: false
      dhcp6: false
      accept-ra: false
      addresses: [10.10.10.1/24]
```
На GW-B замените адреса на 192.168.56.20/24 и 10.20.20.1/24. Для PC-A оставьте только enp0s3 с адресом 10.10.10.10/24 и добавьте под ним:
```yaml
      routes:
        - to: default
          via: 10.10.10.1
```
На Server-B используйте 10.20.20.10/24 и via 10.20.20.1. На каждой VM проверьте `sudo netplan generate`, примените `sudo netplan try` и подтвердите из консоли после проверки связи. На шлюзах `/etc/sysctl.d/99-exam.conf`:
```ini
net.ipv4.ip_forward=1
net.ipv6.conf.all.disable_ipv6=1
net.ipv6.conf.default.disable_ipv6=1
```
Примените `sudo sysctl --system`. Эти файлы обеспечивают сохранение адресов, маршрутов и форвардинга после перезагрузки. [Примеры Netplan](https://netplan.readthedocs.io/en/0.105/examples.html).
